# 容器化实施路线图

spec：`docs/specs/2026-09-15-k8s-containerization-design.md`　日期：2026-09-17

五个阶段，每个阶段结束都有可独立验证的产物。阶段 1 在 gh_skill 仓库，其余在本仓库。

| 阶段 | 仓库 / 分支 | 做什么 | 产物 | 验证 | 详细计划 |
|---|---|---|---|---|---|
| **1. 技能侧改动** | gh_skill `feat/k8s` → `skills-v13.0` | 6 项：GSDB_HOME 守卫；会话不存中间件地址；findings 带执行人；gaussdb-kb 拆成查询 / 导入两个 skill；知识库写入互斥 + 原子写；只读知识库明确提示 | 新标签 `skills-v13.0`，18 个 skill | gh_skill 全部验收层（单测 py3.9/3.12、矩阵 60×2、harness 80、会话 e2e、kb 三态）| `2026-09-17-phase1-skills.md` |
| **2. 后端镜像** | 本仓库 `docker/` | 一个 Dockerfile 两个 target：`gaussdb-agent-runtime`、`gaussdb-agent-kb-import`；`entrypoint.sh`（目录、config.yaml 重生成、`.owner` 独占、`integrity_check`、日志清理、退出 checkpoint + 备份）；`opencode.jsonc` 模板（share 禁用、`{env:}`）；预置 opencode 1.18.27、rg、models.json；x86_64 + aarch64 | 两个镜像 + `scripts/smoke-image.sh` | `docker run` 挂本地目录当 NAS：登录、health、kb query；kb-import 的 ingest；`.owner` 冲突与自检恢复在容器里单独测 | 阶段 1 完成后写 |
| **3. k8s 清单与集群验证** | 本仓库 `k8s/`、`scripts/` | runtime / kb-import Deployment 模板、NAS PVC、NetworkPolicy、Secret/ConfigMap 样例；OrbStack k8s 用 hostPath 当 NAS | 清单模板 + `scripts/verify-cluster.sh` | spec §12 第 1–6 项：隔离、无状态重建、知识库流转、只读、自检恢复、gh_skill 验收在 Pod 内重跑 | 阶段 2 完成后写 |
| **4. 文档与发布** | 本仓库 `docs/` | 环境变量契约、网关契约（给平台的一页）、交付手册容器化章节（含 §6.3 措辞与客户确认表）、离线镜像包脚本 | 交付包 | 从包装出副本再跑冒烟 | 阶段 3 完成后写 |
| **5. 客户环境** | — | NFS 压测 5 个工作日、客户签字、平台对接网关 | 压测报告 | spec §6.2 ⑥ | 客户提供 NFS 版本与 storageclass 后定 |
| **6. frontend 与 CLI** | 本仓库 | deepseek-harness 前端改造为 frontend 镜像；`attach` / ttyd 接入说明；或先用 `opencode web` | frontend 镜像 | 浏览器完整走一次登录、诊断、知识库查询 | 阶段 2 完成后评估 |

阶段 1 的 6 项做的顺序：GSDB_HOME 守卫 → 会话不存地址 → 执行人 → kb 拆分 → 互斥与原子写 → 只读提示。前三项互不相关且小；拆分改目录布局，后两项在新布局上做。

gh_skill 的 `release/v12.9` 分支不动，现场热修走它。
