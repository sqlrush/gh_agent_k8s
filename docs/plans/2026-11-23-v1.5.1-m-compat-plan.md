# v1.5.1 方案：业务库 M 兼容（sql_compatibility='M'）

> 状态：**已实现（2026-11-23）**，见文末「实现结果」。原状态：待评审。分支 `feat/m-compat-151`（基于 main 72104df = agent-v1.5.0 + 发版后文档）。
> 依据：现场 2026-11-20 反馈表（15 条脚本在 M 兼容业务库报错）+ GaussDB 25.1.32 官方文档《M-Compatibility 开发者指南》。
> 标注：**[文档]** = 官方文档能确认；**[实测]** = 必须在真实 M 兼容库上跑过才能定稿。

## 0. 目标与边界

- 41 条业务库脚本（`database_type: appbusiness`）在 A、M 两种业务库上都能正常执行，结果口径一致。
- 模型自己写的 SQL（改写、建索引、示例语句）按业务库的兼容模式写（方案 C：改提示词，范围见 §3）。
- 脚本名、参数、**输出列名一律不变**，调用方读列的代码不动。
- A 兼容库上的行为与 1.5.0 完全一致（§6 用回归证明）。
- 不在范围：B 兼容模式（文档写明不推荐、不再演进；登录输出照写模式，按 A 处理并提示）；直连模式下的虚拟索引验证（hypopg，现场走中间件不触发）。

## 1. 15 条报错的结论

| 脚本 | 执行库 | 原因 | 处理 |
|---|---|---|---|
| health.unused_index、explain.kernel_funcs | 业务库 | `\|\|` 在 M 是逻辑或 | 1.5.0 已改 concat；本版给 concat 里的名字列加 `::text`，实测 |
| lockwait.pairs | 业务库 | 同上 | 同上，另 COALESCE 名字列加 `::text` |
| health.stale_stats | 业务库 | 同上；另 `CAST(… AS float8)` 不在 M 的 CAST 目标类型里 [文档] | 改 `* 1.0 /` |
| health.partitions | 业务库 | `max()`/`COALESCE()` 处理 `"char"` 列（partstrategy）报 un support type | CASE 映射成文字常量 |
| health.table_writes | 业务库 | COALESCE(name, name) 推导成 `any`；外层 `"table"` 在 M 是字符串常量（修完报错后会静默变成字面 'table'）[文档] | 去掉派生表，一层查询，最外层 `AS "table"` |
| sqlreview.tables / indexes | 业务库 | `AS table`，TABLE 在 M 是保留字 [文档] | `AS "table"`；去掉 `ARRAY[]::text[]` 字面量 |
| procinfo / proctune.locate_search | 业务库 | M 不支持 ILIKE | `lower(x::text) LIKE lower('%…%')` |
| procinfo / proctune.source_adm | 业务库 | M 库只继承部分系统视图，没有 ADM_* [文档] | SQL 不改（无对等写法）；M 库不调用，报告写原因 |
| memanalyze.wlm_sql / wlm_operator / wlm_operator_hist | postgres 库 | **非兼容问题**：执行账号无 WLM 函数执行权限 | SQL 不改；技能已自动改从 SQL 执行历史取；原因文字写清，交付说明写授权办法 |

## 2. 白名单脚本改写（15 条，`agent/scripts/registry/`；其中 13 条在交付白名单里）

通用规则（同时写进守卫测试 §5）：
1. 名字类列（`name` 类型：nspname、relname、proname、pkgname、usename、attname、conname、schemaname、indexrelname…）
   进 `COALESCE` / `CASE` / `concat` / `UNION` / 聚合时一律 `::text`；直接 SELECT、与字面量比较不用转（`vacuum.bloat_estimate` 等在现场已跑通）。
2. 双引号只用在最外层列别名 `AS "table"`，表达式里不引用双引号名。
3. 不用 ILIKE、`||`、`ARRAY[...]` 字面量、`::text[]`、`CAST(… AS float8/int8/…)`。
4. `::` 保留（A、M 共同支持；M 文档称「不建议」，m_format_dev_version='s2' 时行为改变）[实测]。

### 2.1 照片内（8 条）

**health/partitions.yaml**（`"char"` 列不再进聚合）
```sql
SELECT n.nspname AS schema,
       c.relname AS "table",
       count(*)  AS parts,
       COALESCE(max(CASE p.partstrategy WHEN 'r' THEN 'r' WHEN 'i' THEN 'i' WHEN 'l' THEN 'l'
                                        WHEN 'a' THEN 'a' WHEN 'h' THEN 'h' WHEN 'n' THEN 'n'
                                        ELSE '?' END), '') AS strategy
  FROM pg_partition p
  JOIN pg_class c     ON c.oid = p.parentid
  JOIN pg_namespace n ON n.oid = c.relnamespace
 WHERE p.parttype = 'p'
   AND n.nspname NOT IN ('pg_catalog','information_schema','snapshot','dbe_perf',
                         'dbe_pldeveloper','cstore','pg_toast')
 GROUP BY n.nspname, c.relname
 ORDER BY parts DESC;
```
策略码取值见 PG_PARTITION.partstrategy（r/i/l/a/h/n）[文档]；输出仍是单字母，collectors.py 不动。

**health/table_writes.yaml**（去掉派生表与外层 `"table"` 引用）
```sql
SELECT CASE WHEN s.schemaname = 'pg_toast' THEN pn.nspname::text ELSE s.schemaname::text END AS schema,
       CASE WHEN s.schemaname = 'pg_toast' THEN pc.relname::text ELSE s.relname::text END AS "table",
       (s.schemaname = 'pg_toast') AS is_toast,
       s.n_tup_ins, s.n_tup_upd, s.n_tup_del,
       CASE WHEN s.schemaname = 'pg_toast' THEN pg_relation_size(s.relid) END AS toast_bytes
  FROM pg_stat_all_tables s
  LEFT JOIN pg_class pc     ON s.schemaname = 'pg_toast' AND pc.reltoastrelid = s.relid
  LEFT JOIN pg_namespace pn ON pn.oid = pc.relnamespace
 WHERE s.n_tup_ins + s.n_tup_upd + s.n_tup_del > 0
   AND ((s.schemaname <> 'pg_toast'
         AND s.schemaname NOT IN ('pg_catalog','information_schema','snapshot','dbe_perf','dbe_pldeveloper','cstore'))
     OR (s.schemaname = 'pg_toast' AND pn.nspname IS NOT NULL
         AND pn.nspname NOT IN ('pg_catalog','information_schema','snapshot','dbe_perf','dbe_pldeveloper','cstore','pg_toast')))
 ORDER BY s.last_data_changed DESC NULLS LAST
 LIMIT {{limit}};
```
与原口径逐项等价：普通表取自身；TOAST 折回所属表；找不到所属表的 TOAST 与系统 schema 一并排除。NULLS LAST 在 M 支持 [文档]。

**health/stale_stats.yaml**：`concat(n.nspname::text, '.', c.relname::text)`；排序里
`CAST(abs(cur_pages - frozen_pages) AS float8) / frozen_pages` → `abs(cur_pages - frozen_pages) * 1.0 / frozen_pages`。
注：M 里 `/` 结果是小数，`cur_pages` 会带小数位，Python 侧 `as_int` 已按截断处理。

**sqlreview/tables.yaml**
```sql
SELECT
  n.nspname::text AS schema,
  c.relname::text AS "table",
  EXISTS (SELECT 1 FROM pg_constraint pk WHERE pk.conrelid = c.oid AND pk.contype = 'p') AS has_pk,
  COALESCE((SELECT array_to_string(array_agg(fk.conname::text), ',')
              FROM pg_constraint fk
             WHERE fk.conrelid = c.oid AND fk.contype = 'f'), '') AS fks,
  COALESCE((SELECT array_to_string(array_agg(a.attname::text ORDER BY a.attnum), ',')
              FROM pg_attribute a
             WHERE a.attrelid = c.oid AND a.attnum > 0 AND NOT a.attisdropped), '') AS columns
FROM pg_class c
JOIN pg_namespace n ON n.oid = c.relnamespace
WHERE c.relkind = 'r' AND n.nspname = '{{schema}}'
ORDER BY c.relname;
```
空集时 `array_agg` 得 NULL → COALESCE 成 ''，与原来 `array_to_string(ARRAY[]…)` 的 '' 相同。`array_agg` 在 M [实测]；不行则加 M 专用版（`group_concat`）并由代码按兼容模式选。

**sqlreview/indexes.yaml**：两个候选，实测定。
- 候选 1（改动最小）：`AS "table"`；`COALESCE((SELECT array_to_string(array_agg(…), ',') …), '')` 同上；保留 `(string_to_array(ix.indkey::text, ' '))[s]` 下标 [实测]。
- 候选 2（不用数组下标）：按位置 `generate_series(1, ix.indnatts)` 取 `pg_get_indexdef(ix.indexrelid, k.ord, false)`，再与 `pg_attribute.attname` 关联（表达式列自然被排除，与原口径同）；
  代价：需要加引号的列名（大小写混写、特殊字符）关联不上，会少列。候选 1 在 M 跑不通才用候选 2。

**procinfo/locate_search.yaml、proctune/locate_search.yaml**（两份相同）
```sql
SELECT 'proc' AS kind, n.nspname::text AS nspname, COALESCE(k.pkgname::text, '') AS pkgname, p.proname::text AS proname
FROM pg_proc p
LEFT JOIN pg_namespace n ON n.oid = p.pronamespace
LEFT JOIN gs_package k ON k.oid = p.propackageid
WHERE lower(p.proname::text) LIKE lower('%{{name}}%')
  AND (n.nspname IS NULL OR (n.nspname NOT LIKE 'pg_%' AND n.nspname NOT LIKE 'dbe_%'
       AND n.nspname NOT IN ('information_schema', 'pkg_service', 'pkg_util', 'sqladvisor', 'db4ai',
                             'snapshot', 'blockchain', 'cstore', 'pmk', 'coverage')))
UNION ALL
SELECT 'package' AS kind, n.nspname::text AS nspname, k.pkgname::text AS pkgname, '' AS proname
FROM gs_package k
LEFT JOIN pg_namespace n ON n.oid = k.pkgnamespace
WHERE COALESCE(length('{{package}}'), 0) > 0 AND lower(k.pkgname::text) LIKE lower('%{{package}}%')
ORDER BY 1, 2, 3, 4
LIMIT 40;
```
`length('')` 在 A 是 NULL、在 M 是 0，COALESCE 后都 > 0 不成立，判空写法两边一致。M 库默认升序 NULLS LAST，与 A 相同 [文档]。

**login/current_db.yaml**（登录探针多取兼容模式与表名大小写参数）
```sql
SELECT current_database() AS db, current_user AS usr,
       (SELECT datcompatibility::text FROM pg_database WHERE datname = current_database()) AS compat,
       (SELECT setting FROM pg_settings WHERE name = 'lower_case_table_names') AS lctn;
```
用 pg_settings 而不是 current_setting：A 库没有该参数，current_setting 会报错，pg_settings 只是取不到行（NULL）。
现场没导本版增量时探针仍是旧 SQL，没有 compat 列 → 兼容模式记「未知」，按 A 处理并在登录输出里提示导入增量。
