巡检大盘 UI 方案说明

2026-11-11 · 配合 可交互原型（假数据，不连后端）与 智能体巡检方案 · 视觉沿用现有大盘（frontend/styles/base.css，R6「智能运维舱」）
一句话：现有大盘回答「这个库怎么样」，巡检大盘回答「这个应用 / 这个 IDC 下哪些库最该先管」。它不重做单库页面—— 总览和排名负责「找到」，点一下就下钻到现有的健康 / Top SQL / WDR 大盘去「看清」，再点「深挖 →」交给智能体对话去「查透」。

2. 级别、状态与标记

标记规则
严重 告警 关注 正常与单库大盘同一套：脚本按阈值判定（common/finding.py 的 0～3），模型不改。库的级别 = 这个库最坏的一条发现。形状也不同（八角 / 三角 / 圆点 / 对勾），色弱也能分。
未采到（虚线圈）维度 available=false 或任务失败：不算正常，单独计数，进覆盖率。原因（没切到业务库、采集超时、权限不足）写在库详情里。
样本不足比率类指标（回滚率等）在窗口内事务数不足 1000 时不参与排名，值显示「样本不足」，排在最后。
新增 / 持续 / 已消除按「同一库 + 同一发现编号」与上一次巡检比较。
分位 Pn该值在当前范围（应用或 IDC）内的位置；P90 及以上标红（事务量这类「量」指标不标红）。
所在实例标签库行上带出实例的级别图标：库本身没问题、但实例连接打满 / 复制延迟时，一眼能看到。
实例级横幅切到实例榜时出现：说明这些数据含该实例所有库、不拆到库。

3. 指标定义

3.1 库榜（同一范围内所有库统一排名）

维度定义来源（执行库）窗口排序 / 阈值
健康级别（默认）严重数 → 告警数 → 关注数 → 新增数库级发现 + 可归属到库的实例级发现本次降序；不编综合分

4. 交互

操作效果
顶栏 IDC / 应用 / 巡检批次全站范围切换；URL 带参数，可分享（实现时 ?idc=&app=&run=）。选「全部应用」时总览多出「各应用对比」。
圆环图例点一档跳到排名页、按该级别筛选。
趋势柱点一根切到那一次巡检（整页按那一次重画，「与上次」也随之变化）。
维度条点一行跳到排名页的对应维度。
摘要里的证据编号打开对应库的详情抽屉。摘要里每句都必须带编号，没有编号的句子不显示。
排名：维度分段 / 表头「值」/ 级别筛选 / 搜索切维度、切升降序、多选级别、按库名 / 实例 / 应用过滤。
点表格一行右侧抽屉打开库详情；Esc 或点遮罩关闭。
下钻 ↗新标签页打开现有单库大盘：库级 → /dash/health?src=inspect&key=api/10-0-0-21-acct；实例级 → /dash/topsql、/dash/wdr 带 …-postgres 键。
深挖 →复用现有大盘的深挖：以点击的人的身份经网关建会话、发首句、新标签页打开对话；首句带巡检编号与该库结论，模型不必重新采一遍才知道发生了什么。
发起巡检弹窗选套餐（快检 / 日检 / 深检）、范围、原因（记审计），提交后在任务页看到排队 → 进行中 → 完成。需要 inspect-operator 角色。
告警记录点一行打开告警涉及的库 / 实例的详情；「巡检记录」跳到那次快检；已自动深挖的显示「深挖会话 ↗」。

5. 与现有大盘的复用

现有巡检大盘怎么用
前端镜像（纯静态、零构建）同一个镜像加 4 个页面：frontend/pages/inspect-overview.js · inspect-rank.js · inspect-runs.js · inspect-alerts.js（+ 清单页），路由 /dash/inspect/*，shell.js 按 pathname 切页（现有机制）。
lib/ui.js、lib/viz.js、lib/fmt.js级别图标、标签、圆环、条形、走势直接用；新增一个「堆叠趋势柱」与「值条 + 分位」两个小部件。
lib/data.js加一个数据源开关：src=inspect 时从 /inspect/reports/… 取（巡检目录，报告契约相同），否则照旧 /reports/…（本人目录）。单库大盘因此不用改页面就能显示巡检结果。
网关三路分发加第四路 /inspect/* → 巡检服务的只读接口；身份照旧取 SSO 头，按角色放行（inspect-viewer 看，inspect-operator 发起；可按应用授权）。
普通 / 文艺两种风格巡检页沿用同一套变量，两种风格都能切。原型只画了普通风格。
深挖（建会话 + 首句 + 新标签页）原样复用，首句模板多一种「来自巡检」的写法。

6. 数据口（大盘只读）

请求用在
GET /inspect/rank/<应用>/index.json批次下拉、近 14 次趋势（每次一行：时间、问题数分级、覆盖率）
GET /inspect/rank/<应用>/<run_id>.json总览全部模块、排名页（库榜与实例榜都在这一份里，前端只做筛选与排序）
GET /inspect/reports/<skill>/<实例键>/…库详情抽屉、下钻后的单库大盘
GET /inspect/api/v1/runs?…、/alerts?…任务页、告警页

IDC 或「全部应用」范围：前端并行取各应用的 rank 文件后合并（应用数一般几十个以内）；P2 若应用多到上百，由巡检服务预先生成 IDC 级汇总文件。

7. 原型的局限

  • 数字全部是假数据（按随机种子生成，刷新不变）；地址一律是 10.0.0.x 占位，库名、应用名都是虚构的。
  • 「下钻」「深挖」「上传清单」只弹出提示，说明实际会打开什么；「发起巡检」会在任务页模拟一次进度。
  • 只做了桌面宽度（与现有大盘一致，不做移动端）；只画了普通风格。
