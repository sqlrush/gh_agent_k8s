设计说明（给确认用，实现时不出现）

  • 数据来源：gaussdb-topsql --format json，行字段就是 sql_id / query / calls / total_sec / avg_ms / rows，六个，没有更多。页面上所有数字都能从这六个字段算出来（占比 = 单条 / 全部之和）。
  • 五个维度页签 = 脚本的五个 --by：总耗时 / 平均耗时 / 调用次数 / 逻辑读 / 返回行。切页签 = 换排序重新取数（每次取 Top N + 全量合计）。
  • 与 dsh-k8s sqlreview-r5 的差别：那边有 DB Time / CPU / IO 三个维度的堆叠条，来自 dbe_perf.statement 的更多列；我们的 topsql 脚本目前只取六列，所以只有一根「当前维度」的堆叠条。要多维度就得扩脚本（白名单要加列，客户侧走版本 DML）——这是一个要你拍板的取舍。
  • 逐条卡的「优化建议」来自 gaussdb-sqltune：某条 SQL 跑过调优就显示摘要与优化后 SQL，没跑过显示「尚未调优 · 调优 →」。系统对象的 SQL 不会出现（sysobjects 策略在取数侧已过滤）。
  • 「自视图重置以来」是 dbe_perf.statement 的真实语义：它是累计视图，不是时间窗口。要看「最近一小时」应该去 WDR 大盘。
