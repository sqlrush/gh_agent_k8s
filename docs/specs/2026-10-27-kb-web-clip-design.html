知识库导入扩展：内网网页剪藏 · 扫描件 PDF · PPT

需要登录的内网网页，由用户在已登录的浏览器里一键剪藏进知识库；扫描件 PDF 与 PPT 进入同一条导入流程。导入效果与现有一致：从无结构的材料里筛出现象、根因、处置等有效信息，形成 L0–L3 渐进式披露。

0　结论先说

「用户先在浏览器登录、我们直接访问 URL」在服务端走不通。网页若由导入容器去抓，请求从集群里发出，带不上用户浏览器的登录状态， 内网 Wiki 只会返回登录页。要用浏览器的登录状态，读取页面这一步必须发生在用户的浏览器里。
方案：网页剪藏。管理员在要导入的页面上点一下浏览器书签「导入知识库」——书签在这个已登录的页面里取出正文（含 JS 渲染后的内容）与页内图片， 交给我们的剪藏页，剪藏页把材料存进知识库收件目录，并自动在导入环境里发起「导入这一页」。之后的格式化与入库和现有流程完全一样。
好处：不需要我们做登录；不需要平台给导入环境开任何内网访问（网络策略不动）；页面内容只在贵方内网流转。
需求做法改动量
需要登录的内网网页浏览器书签剪藏 → 剪藏页 → 收件目录 → 自动发起导入（第 2–4 节）中（约 2.5 天）
书签用不了时的退路浏览器「另存为 → 网页，单个文件（.mhtml）」，拖进剪藏页上传；同一套解析小（含在上面）
多个页面逐页剪藏后一次性说「导入刚才剪藏的几页」；顺着目录页爬取放第二版小
扫描件 PDF每页渲染成图片，交给模型像读照片一样读（第 5 节）小（约 0.5 天）
PPT（.pptx）直接解析幻灯片文字、表格、备注；幻灯片里的图片交给模型看（第 6 节）小（约 0.5 天）
测试单测 + 测试环境端到端（Mac 上起一个需要登录的模拟 Wiki）约 1 天

合计约 4.5 天。不需要客户数据库做任何改动；白名单不变。

1　整体流程

  1. 一次性安装书签（由模型指导）：管理员在导入环境里第一次贴链接或说「导入这个网页」时，模型按 skill 里预置的引导，一步一步带管理员把「导入知识库」装到书签栏（见 2.3）。书签里写好了本系统的地址，每套部署各一份，由安装页生成。
  2. 剪藏：在已登录的 Wiki 页面上点书签 → 弹出剪藏页窗口，显示标题、来源、正文字数、图片数 → 点「导入」。
  3. 自动发起导入：剪藏页把材料存进本人导入环境的收件目录，并在导入环境里新开一个会话，发出「导入剪藏 clips/<批次>」；页面跳到这个会话。
  4. 模型整理、人确认：模型按现有规矩判断这是工单还是规范 / 手册 / Wiki 等，筛出现象、根因、处置等有效信息，给出类型与摘要请管理员确认；确认后校验、入库、建索引。

多页：逐页剪藏，最后说「导入刚才剪藏的几页」即可，模型按批次逐个处理。在对话里直接贴 URL 时，模型会回复「这个页面需要登录，请在浏览器里打开它并点『导入知识库』书签」。

2　书签与剪藏页（浏览器侧）

2.1 书签做什么

  • 在当前页面（同源、已登录）取 document.documentElement.outerHTML——是 JS 渲染之后的内容，Confluence 这类动态页面也取得到；连同 URL、标题、抓取时间。
  • 页内图片：同源图片用当前登录状态取回（数量、单张与总大小有上限，默认 30 张 / 5 MB / 30 MB），跨源且不允许读取的图片跳过并在清单里注明。
  • 打开剪藏页窗口，等它回「就绪」后用 postMessage 把材料交过去，只发给本系统的源。

2.2 剪藏页做什么

  • 只接受来自名单里的网站的材料（gateway-config 新增 KB_CLIP_ORIGINS，如 https://wiki.内网,https://confluence.内网；空 = 关闭剪藏），并核对消息确实来自打开它的那个窗口。
  • 预览后由管理员点「导入」；同源上传给网关（带着本系统自己的登录状态，不涉及 Wiki 的凭据）。
  • 书签被页面安全策略拦住时的退路：剪藏页支持拖入「另存为 → 网页，单个文件（.mhtml）」或 .html 文件上传，后续处理相同。
要在贵方 Wiki 上实测的一点：个别站点的内容安全策略（CSP）可能限制书签脚本或弹窗。主流浏览器对用户主动点击的书签一般放行； 真遇到拦截，就用 .mhtml 退路，或由贵方把同一段脚本做成内部浏览器插件统一下发。

这一切都由网关自己提供（剪藏页、安装页都是网关返回的静态页面），不依赖前端方改代码。

2.3 书签安装由模型指导（skill 里预置提示词）

  • 先查状态再说话：新增 kb.py clip status，输出剪藏是否开启、允许的网站、安装页地址、本人最近一次剪藏时间。模型据此决定说什么： 没开启就请平台配 KB_CLIP_ORIGINS；链接的网站不在名单就如实说明；剪藏过的人直接说「在页面上点书签」，不重复安装。
  • 一步一步带：先问用的浏览器（Chrome / Edge / 360 安全浏览器 / 奇安信可信浏览器 / Firefox），按对应步骤；每步等用户回「好了」再说下一步。
  • 书签代码不由模型写：书签代码由安装页按本部署的地址生成，模型只给安装页的链接（由 status 输出、原样贴出），不拼写、不修改 javascript: 代码。 拖不动时引导用户用安装页上的「复制书签代码」手工新建书签。
  • 排障表预置：点了没反应、弹窗被拦、剪到的是登录页、来源网站不在名单、图片缺失，各给一句原因与处理；页面安全策略拦住书签时引导改用 .mhtml 退路。
  • 边界：模型不访问链接（它没有联网能力，也带不上用户的登录状态）；不让用户把 Wiki 的 cookie、口令发给它。

## 网页剪藏（内网网页导入）

触发:用户给出 http(s) 链接,或说「导入这个网页 / Wiki / Confluence 页面」「剪藏」。

1. 先跑 `kb.py clip status`。按输出:
   - 剪藏未开启 → 告诉用户需要平台在 gateway-config 配 KB_CLIP_ORIGINS(列出要导入的网站),到此为止;
   - 链接所在网站不在允许名单 → 如实说明,请平台加入名单;
   - 本人剪藏过 → 跳到第 3 步。
2. 不要访问这个链接:你没有联网能力,也带不上用户的登录状态。说明「这个页面需要登录,要在你已登录的浏览器里用书签剪藏,
   第一次用要装一下书签,我带你装,大约一分钟」,然后按 references/web-clip-guide.md 一步一步引导,每步等用户回「好了」:
   a. 问用的浏览器,按对应步骤;
   b. 让书签栏显示出来(Chrome / Edge:Ctrl+Shift+B,Mac 上 Cmd+Shift+B);
   c. 打开安装页:贴出 status 输出里的安装页链接,原样贴,不要自己拼地址;
   d. 把安装页上的「导入知识库」按钮拖到书签栏;拖不动就点「复制书签代码」,新建书签,名称写「导入知识库」,网址粘贴进去。
      书签代码只用安装页给的,你不要自己写或改任何 javascript: 代码。
3. 请用户打开要导入的页面(先确认已登录),点书签「导入知识库」,在弹出的剪藏窗口里核对标题与字数后点「导入」。
   剪藏页会自动新开会话发出「导入剪藏 clips/<批次>」,按标准导入流程处理(判断类型、筛出现象 / 根因 / 处置、请用户确认)。
4. 出问题按 web-clip-guide.md 的排障表回答:点了没反应 / 弹窗被拦 / 剪到登录页 / 来源不在名单 / 图片缺失 / 页面安全策略拦截(改用 .mhtml)。
5. 不要让用户把 Wiki 的 cookie、口令或令牌发给你;用户主动贴了,提醒用户立即删除并修改口令。

3　接收与存放（导入环境侧）

  • 网关：新增 POST /kb-import/clip/upload，只对知识库管理员开放（与现有 /kb-import 同一套身份校验），按工号转给本人的导入环境；导入环境没起来时先起（与现在进入导入环境一致）。
  • 导入容器里的剪藏接收服务（新，标准库实现，与 opencode 同一容器、同一身份）：校验大小、类型（HTML / 图片按文件头判断，不信后缀）、文件名，写进 kb/inbox/clips/<日期-序号>/：page.html（原样快照）、meta.json（URL、标题、抓取时间、sha256、图片清单与跳过原因）、images/。
  • 网络策略：只放行网关 → 导入容器的接收端口这一条；导入容器的出网不变。
  • 自动发起导入：剪藏页经网关调用导入环境的 opencode 接口新建会话并发出导入指令（与现在网页里发消息走同一条路）。

4　网页 → 干净的 md（kb.py clip）

现有的 HTML → md 模块是为官方文档（华为 DITA 页面）写的。内网 Wiki / Confluence / 门户页面结构各异，新增通用的「找正文」：

  1. 找正文区：依次找 <main>、<article>、[role=main]、Confluence 的正文区、#content 等常见容器；都没有时取文字最多、链接密度最低的区块。
  2. 去噪：导航、页头页脚、侧栏、面包屑、评论区、点赞与分享、脚本样式一律去掉。
  3. 保留结构：标题层级、段落、列表、表格（转 md 表格）、代码块、引用、链接（文字 + 地址）、图片（换成本地 images/ 引用）。
  4. 编码：按页面声明，缺失时 utf-8 → gb18030 依次试（与现有一致）。
  5. 抽不出来不假装：正文过少（如只剩登录页、无权限页、空白页）时拒绝并说明原因——不把「请登录」入库成一条知识。

产出 clips/<批次>/page.md，开头记来源 URL、标题、抓取时间与 sha256，交给下一步。

5　扫描件 PDF

  • 现在：检测出没有文字层就拒绝（不做 OCR）。改为：每页渲染成图片（导入镜像里已有 poppler 的 pdftoppm，不加依赖），像照片一样交给模型读。
  • 页数上限默认 30 页一批（可调），更长的分批读；读出的内容标 extracted_by: model，保留「看不清的地方问用户、不猜」的规矩。
  • 前提与照片相同：模型服务支持图片输入，且 agent-config 配了 MODEL_INPUT_MODALITIES=text,image；没开时如实说明是平台配置。
  • 混合 PDF（部分页有文字层）：有文字的页照常脚本抽取，只有无文字的页交给模型看。

6　PPT（.pptx）

  • 与 docx 同法，标准库解压读 XML：每张幻灯片的标题、正文段落（保留项目符号层级）、表格、演讲者备注，按「第 N 页」分段输出 md。
  • 幻灯片里的图片（截图、架构图、监控曲线）落到 images/，在 md 里标出所在页；需要时交给模型看图补充（同样标 extracted_by: model）。
  • 老格式 .ppt 不在本次范围（与 .doc 一样需要额外转换器），会提示另存为 .pptx。

7　导入效果：与现有流程一致

新来源只负责把材料变成干净的文本与图片，之后的整理与入库完全复用现有流程，效果与现在导入 docx / 工单表格一致：

材料是什么怎么整理入库后
故障处理记录、事件复盘、工单页标准化成六要素：时间、系统 + 现场（现象）/ 判断（根因）/ 处置（方案）/ 复发标志；原文没写的显式写「原文未写明」，不编； 同一页写了多起事件时拆成多单案例（含候选原因、取证顺序、排除理由、区分证据）
操作手册、应急预案处置手册模板：适用场景、执行前提、步骤、回退、风险处置手册
规范、制度、配置要求按条款拆分，标出适用范围规范条款
已知问题、版本缺陷说明受影响版本、现象、规避方法、厂商结论已知缺陷
系统介绍、架构说明环境画像（只写连接别名，不写地址与口令）环境画像
经验总结、FAQ、零散笔记Wiki 经验，筛掉与数据库运维无关的内容Wiki
  • 筛选有效信息：网页里的寒暄、评论、与数据库无关的段落不进条目；模型给出「保留了哪些、丢掉了哪些」的摘要供管理员确认。
  • L0–L3 渐进式披露：入库后 kb.py index 重建 L0 总索引与 L1 专题导航；条目全文是 L2；原始网页快照、扫描件、PPT 原件进 evidence/ 作为 L3，引用时可追溯到原页面与抓取时间。
  • 出处：条目记来源 URL 与抓取时间；回答里引用时照常上色并注明出处。页面后来改了，重新剪藏会因 sha256 不同提示「内容有更新」。
  • 安全：沿用现有的脱敏规则（口令、密钥等）；材料只存贵方 NAS，不出内网。

9　请确认

  1. 需要登录的页面改用「书签剪藏」（用户在页面上点一下），而不是在对话里输入 URL —— 这是在不碰登录、不开内网访问的前提下唯一稳妥的做法。书签安装由模型按 2.3 引导。可以吗？
  2. 不需要登录的内网页面，要不要另外支持「在对话里贴 URL 直接抓」？要的话需平台给导入环境开放这些网站的出网，并加防滥用限制；我的建议是本版不做，统一用剪藏。
  3. 扫描件 PDF 与 PPT 按第 5、6 节一起做。
