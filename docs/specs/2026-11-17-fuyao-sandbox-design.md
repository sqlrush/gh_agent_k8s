# 设计：Fuyao 沙箱运行模式（`RUNTIME_MODE=fuyao`）

日期：2026-11-17。基线：`agent-v1.4.14`。分支：`feat/fuyao`。目标版本：`agent-v1.5.0`。

## 1. 目标与范围

在 openFuyao 沙箱平台（OpenSandbox + Flux + E2B / Firecracker 微型虚拟机）上运行智能体：**每个用户一台沙箱**，知识库管理员的导入环境同样一台沙箱。

- 网关新增第三种运行模式 `fuyao`，与 `ondemand`（按需建 Pod）、`pool`（固定池化）并列，改配置切换；现有两种模式的代码路径不动。
- 留在 K8s 的组件：网关、大盘前端、标准知识库安装 Job，以及本设计新增的两个集群服务——凭据代理服务、状态服务。
- 不在范围：平台自身的安全加固（见 §9 平台前提）。

## 2. 平台实测事实（决定设计的约束）

以下均为 PoC 实测或读平台源码所得，平台升级后需重新核对。

| 事实 | 对设计的影响 |
|---|---|
| 创建沙箱：`POST /v1/sandboxes`，`extensions.sandboxGroup` 指定沙箱组；不带 `extensions.poolRef` 时必须带 `resourceLimits`；`image.uri` 填模板名 | 网关后端按此组装请求 |
| 建沙箱 0.1–0.6 秒 | 首次进入的等待主要在启动器与状态载入 |
| 虚拟机规格（vCPU、内存、磁盘）由**模板**决定，沙箱组规格只是 K8s 侧预留 | 构建模板时定足规格 |
| 创建请求里的 `env`、`entrypoint` 不进虚拟机 | 启动器：沙箱建好后经 envd 下发配置并启动 |
| 创建请求里的 `volumes` 不往下传，Flux 的 Sandbox 对象没有卷字段 | 沙箱只有本地盘；NAS 由集群侧**状态服务**读写 |
| 出网规则不往下传（只传模式字段） | 出网限制由平台在宿主机侧实现（§9） |
| envd（49983）的 Connect 接口可按命令带环境变量、指定用户执行；它会等待子进程 | 启动器以 `systemd-run` 起后台服务 |
| 虚拟机在 Pod 网段有独立地址，集群内可直连任意端口，SSE 实时 | 网关直连 `虚拟机地址:4096 / 4097 / 4095`，转发代码沿用 |
| 虚拟机 DNS 为公网地址，解析不了集群域名 | 集群服务一律用 ClusterIP 下发 |
| `PATCH /v1/sandboxes/{id}/metadata` 可用，metadata 即 Sandbox 对象标签，可按 metadata 列举 | 工号、角色、活动时间记在 metadata |
| 暂停约 2 秒、恢复约 3 秒，内存快照完整续上 | 粘性保留：闲置时暂停、回来恢复 |
| 恢复后虚拟机地址会变，而 `/endpoints/{port}` 仍返回旧地址 | 见 §6.3 地址发现 |
| 删除即时生效，虚拟机内收不到退出信号 | 销毁前由网关触发收尾同步 |
| 模板构建：`POST /v3/templates`（名称、vCPU、内存）+ `POST /v2/templates/{tid}/builds/{bid}`（`fromImage`）；构建服务只能从平台内部镜像仓库拉取 | 构建脚本先把镜像推到平台仓库再构建 |

## 3. 组件与通路

| 组件 | 位置 | 职责 |
|---|---|---|
| 网关 | K8s | 认身份；为每人申请诊断 / 导入沙箱；登记「沙箱 → 工号」；下发配置并启动；转发；闲置暂停与回收 |
| 凭据代理服务 | K8s（runtime 镜像） | 持有模型 Key、SM2 私钥、各工号 GRMP 令牌；按沙箱令牌认人，加凭据后转发 |
| 状态服务 | K8s（runtime 镜像，挂 NAS PVC） | 用户状态载入、增量回写、收尾、按人加锁；知识库发布与按版本拉取；报告只读 |
| 诊断沙箱 | 虚拟机（runtime 模板） | opencode + 诊断技能；启动器；状态同步客户端；本地盘 |
| 导入沙箱 | 虚拟机（kb-import 模板） | opencode + 知识库技能；剪藏接收；知识库工作副本，完成后发布 |

通路：
1. 浏览器 → SSO → 网关；
2. 网关 → OpenSandbox：建、删、暂停、恢复；
3. 网关 → 沙箱 envd：下发配置、启动、收尾；
4. 网关 → 沙箱 4096 / 4097 / 4095：对话、报告、剪藏；
5. 沙箱 → 凭据代理服务：模型与 GRMP；
6. 沙箱 ⇄ 状态服务：状态与知识库；
7. 状态服务 ⇄ NAS；
8. 网关 → 状态服务：报告只读、登记沙箱。

## 4. 身份与令牌

- 网关为每次绑定生成三样东西：对话口令（同现在）、报告令牌（同现在）、**沙箱令牌**（新增，32 字节随机）。
- 网关向凭据代理服务、状态服务**登记**：`沙箱令牌 → {工号, 角色, 沙箱 ID}`。登记请求用网关与集群服务共享的控制密钥签名，秘密字段加密，复用 `poolauth` 的格式。
- 沙箱只拿到沙箱令牌。凭据代理和状态服务只认登记过的令牌，并按登记的工号限定：凭据代理写入的工号、状态服务允许访问的目录，都只能是本人的。
- 销毁或长期暂停时注销令牌。

## 5. 启动器（沙箱内）

`podctl fuyao-start`，由网关经 envd 以 root 调用，参数和配置以环境变量形式传入：
1. 写配置到 `/run/gsdb/env`（0600）；
2. 凭沙箱令牌向状态服务**载入**本人状态到本地盘（首次为空）；诊断沙箱另拉取客户知识库只读副本；
3. 以 `systemd-run` 用普通用户起 `entrypoint.sh`；它读 `/run/gsdb/env`，同步回写改走状态服务；
4. 等 4096 就绪后返回。

`podctl fuyao-stop`：完整同步一次，等状态服务确认后返回。网关在暂停（可选）和删除前调用。

## 6. 网关

### 6.1 接入

Fuyao 路由器实现与固定池化路由器相同的接口（`target()` / `note_activity()` / `forget()`；异常 `NotActive` / `PoolFull` / `PoolWait`），`server.py` 的池化转发路径直接复用。诊断与导入是两种 kind，对应两套模板与沙箱组。

### 6.2 生命周期

| 事件 | 动作 |
|---|---|
| 交互请求，本人无沙箱 | 建沙箱（metadata：工号、kind）→ 登记令牌 → `fuyao-start` → 返回目标 |
| 交互请求，本人沙箱已暂停 | 恢复 → 地址发现（§6.3）→ 返回目标 |
| 闲置超过 `FUYAO_IDLE_SECONDS` | `fuyao-stop` → 暂停 |
| 暂停超过 `FUYAO_RETAIN_DAYS` 或沙箱接近寿命上限 | `fuyao-stop`（若在运行）→ 删除 → 注销令牌 |
| 转发连接失败 | 重新查询并重试一次；仍失败则按「沙箱不可用」重建 |

活动时间记在沙箱 metadata，两个网关副本共享，节流写入（同 `ACTIVITY_INTERVAL_SECONDS`）。

### 6.3 地址发现

- 主路径：`GET /v1/sandboxes/{id}/endpoints/49983` 取 IP。
- 恢复后平台返回的地址可能过期。备选：启动器在恢复后主动连一次状态服务，状态服务按来源地址回报（依赖 NAT 后的来源地址是虚拟机的 Pod 网段地址，待验证）。
- 无论哪条路，都以对话口令作为最终校验：口令只在本人的沙箱里有效，连错地址时请求会被拒，不会串数据。

## 7. 状态服务

接口（HTTP，沙箱令牌放在 `Authorization: Bearer`）：

| 接口 | 说明 |
|---|---|
| `POST /v1/lease` | 按人加锁（带心跳续期），同一人同一时刻只有一个沙箱持有 |
| `GET /v1/state` | 载入：把本人目录里要本地化的部分打包返回 |
| `PUT /v1/state` | 增量写入：改动文件 + 删除清单；对话库为在线备份后的整库 |
| `POST /v1/state/finish` | 收尾：写入后清掉 dirty 标记 |
| `GET /v1/kb?since=<版本>` | 知识库只读副本（按版本增量） |
| `PUT /v1/kb` | 发布知识库（只限导入沙箱）：写互斥、原子替换、版本号加一 |
| `GET /v1/reports/...` | 报告只读（网关调用） |

写 NAS 沿用 `fdtree` 的规则（逐级不跟随链接、临时文件独占创建再原子改名），载入成功之前不传播删除，与现有 `statesync` 一致。

## 8. 模板

- `docker/Dockerfile.e2b`：以 runtime / kb-import 镜像为底，加启动器、非 root 用户、envd 所需约定；runtime 模板内置官方文档集。
- `scripts/build-e2b-template.sh`：推送到平台仓库 → `/v3/templates` → `/v2/.../builds` → 等待就绪；模板名带版本。
- 快照停在「待命」：只有 envd 与 systemd，没有任何用户身份。

## 9. 平台前提（上线前必须由平台落实）

| 前提 | 原因 |
|---|---|
| envd 需认证，或阻断虚拟机之间、普通 Pod 到虚拟机 envd 端口的访问 | 实测 envd 无认证，一个沙箱可以 root 身份在另一个沙箱里执行命令 |
| 宿主机侧限制沙箱出网，只放行凭据代理服务、状态服务 | 当前平台版本不能按沙箱下发出网规则，实测虚拟机出网不限 |
| OpenSandbox 开启认证 | 生产环境不得免认证 |
| 恢复后的地址可查询 | 见 §6.3 |
| 模板构建服务能拉到我方镜像 | 平台仓库推送账号，或构建服务补根证书 |

## 10. 不变的部分

21 个技能的业务逻辑、根提示词、大盘前端、标准知识库安装、固定池化与按需模式的全部代码路径。

## 11. 实现顺序

1. 网关：OpenSandbox 客户端、envd 客户端、Fuyao 路由器与回收器、配置（含假 OpenSandbox / envd 的单元测试）；
2. 状态服务与 `statesync` 的 HTTP 后端；
3. 凭据代理网络形态与 GRMP 客户端网络模式；
4. 启动器与模板构建；
5. K8s 清单、发版台、手册；
6. 平台端到端验证。
