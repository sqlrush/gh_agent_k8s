# 仓库结构说明

这个仓库装着**容器化交付的全部东西**：四个自建镜像的构建、K8s 清单、接入网关、大盘前端、技能代码、交付文档。

**先记住一句话**：顶层七个目录，各自对应一件事。

```
agent/      技能代码（诊断能力本身）—— 从 gh_skill 同步过来，不在这里开发
docker/     镜像怎么构建、容器启动后做什么
gateway/    接入网关（认工号、建容器、代理、回收）
frontend/   四个大盘的页面（纯静态，不读任何数据）
k8s/        集群清单（部署到 K8s 要的全部 YAML）
scripts/    构建、打包、部署、验证的脚本
docs/       文档（交付给客户的 + 内部的）
```

看不懂某个文件时的通用办法：**打开它，看头几行的注释**。本仓库的约定是每个文件开头
写清「它干什么、为什么这么做、踩过什么坑」，而不是只写文件名的复述。

## ⚠ 部署时要按客户环境改的文件

仓库里几百个文件，**部署时要动的只有下面这些**，全在 `k8s/` 下。其它目录一个字都不用改。
后文各目录的表里，需要改的文件行首也标了 ⚠。

分三档：不改就起不来或连不上的；按情况才改的；以及不是改文件、而是用 `kubectl` 创建的。

### 第一档：必改

| 文件 | 改哪几项 | 填什么 | 不改会怎样 |
|---|---|---|---|
| ⚠ `k8s/base/nas-pv-nfs.example.yaml` | 复制成 `nas-pv-nfs.yaml`，改 `nfs.server`、`nfs.path` | NFS 服务器地址、导出路径 | 存储卷绑不上，所有 Pod 卡在 `Pending` |
| ⚠ `k8s/base/configmap-agent.yaml` | `GRMP_API_HOST`、`GRMP_API_PORT` | 中间件地址、端口 | **Pod 正常启动、界面正常打开，一登录数据库就失败**。清单里带的是示例地址，不会报「缺配置」 |
| | `MODEL_BASE_URL`、`MODEL_ID` | 模型服务地址（**含 `/v1`**）、模型名 | 同上：第一次对话卡住后超时 |
| ⚠ `k8s/base/configmap-gateway.yaml` | `USER_IMAGE_TAG` | 推到内网仓库的那个镜像标签 | 网关拒绝启动（刻意无默认值） |
| | `TRUST_CIDRS` | 客户**反向代理**的地址段（不是用户的） | 与 Secret 里的 `TRUST_SECRET` 二选一即可；两个都空网关拒绝启动 |
| ⚠ `k8s/base/networkpolicy.yaml` | 三处 `10.0.0.0/8` 占位 | 中间件地址段、模型服务地址段、上游反向代理地址段 | 占位段太宽，隔离形同虚设；填错了则 Pod 连不上中间件/模型 |
| | 网关段的 `10.96.0.0/12` / `172.16.0.0/12` | 集群 API Server 的实际地址（`kubectl get endpoints kubernetes -n default`） | 网关连不上 K8s，建不了 Pod |
| ⚠ `k8s/base/gateway.yaml` `frontend.yaml` `vectordb.yaml` `k8s/templates/runtime.yaml` `kb-import.yaml` | 每处 `image:` | 加内网仓库前缀 | `ImagePullBackOff` |

`image:` 那一项用一条 `sed` 统一改，不用逐个打开（见 `部署手册 §1.4`）。

### 第二档：按情况改

| 文件 | 什么情况下改 | 改什么 |
|---|---|---|
| ⚠ `k8s/base/nas-pvc.yaml` | 集群**已有** RWX 的 StorageClass，不想用静态 PV | 只改 `storageClassName: nas` 为客户的类名。否则**不用动** |
| ⚠ `k8s/base/vectordb.yaml` | 集群**没有默认 StorageClass** | `volumeClaimTemplates` 里加 `storageClassName`。它没写类名，靠默认类；没有默认类向量库会卡 `Pending` |
| ⚠ `k8s/base/configmap-gateway.yaml` | SSO 传工号的请求头不叫 `X-Agent-User` | `USER_HEADER`、`ROLES_HEADER` 改成实际头名 |
| | 想改闲置回收时长 | `IDLE_SECONDS`（默认 1800，下限 300） |
| ⚠ `k8s/base/configmap-agent.yaml` | 中间件过渡期只收 Appkey + Timestamp | `GRMP_APPKEY: F-GAUSS-AGENT`、`GRMP_SIGN_MODE: headers-only`、`GRMP_SIGN_TIMESTAMP: s` |
| | 中间件要显式收调用人工号 | `GRMP_USER_ID_HEADER` 或 `GRMP_USER_ID_PARAM`，填中间件给的字段名 |
| ⚠ `k8s/base/configmap-agent-roles.yaml` | SSO **不传**角色头 | `kb-admins` 里列知识库管理员的工号，每行一个。传角色头时这个文件不用 |
| NAS 上的 `kb/kb.yaml` | 要开语义检索 | embedding 端点、模型、维度。不配就是文件模式，检索照常 |

### 第三档：不是改文件，是用 `kubectl create secret` 创建

`k8s/base/secret-*.example.yaml` 四个文件**只是样例，不要改它们、也不要 apply 它们**。真实值这样建：

| Secret | 键 | 来源 | 缺了会怎样 |
|---|---|---|---|
| `model-api` | `MODEL_API_KEY` | AI 平台 | 用户 Pod 起不来，日志指名缺它 |
| `gateway-auth` | `TRUST_SECRET`（≥16 字符） | 自己生成，**同时交给反向代理** | 与 `TRUST_CIDRS` 二选一 |
| | `ADMIN_TOKEN` | 自己生成 | 留空 = 控制 API 关闭，不影响用户 |
| `vectordb-auth` | `GS_PASSWORD`、`KB_RW`、`KB_RO` | 自己生成，**三个不同** | 向量库起不来；或 runtime 拿到读写权限 |
| `grmp-token-<工号>` | `GRMP_AUTH_TOKEN` | **中间件按人签发**，每个用户一个 | 该用户 503「环境未开通」。**开通一个用户 = 建这个 Secret** |
| `grmp-sm2` | `GRMP_SM2_PRIVATE_KEY` | 中间件签发 | 可选。只在完整签名模式下要 |

逐条命令在 `部署手册-从零到上线.md` 阶段 3；每个参数的含义与默认值在 `参数手册.md`。

## `agent/` —— 技能代码（564 个文件，最大的一块）

**这是诊断能力本身，但不在这个仓库里开发。** 它从非容器线的 `gh_skill` 仓库整体同步过来，
再做容器适配。所以看到这里的改动，要想到「另一条线是不是也要改」。

`agent/UPSTREAM` 记录每次同步的来源版本与改了什么，出问题先看它。

### `agent/skills/` —— 19 个技能

每个技能一个目录，客户对话时模型实际调用的就是这些：

| 技能 | 干什么 |
|---|---|
| `gaussdb-login` | 登录、建会话句柄。所有其它技能的前置 |
| `gaussdb-health` | 整体健康巡检（会汇总下面几个子技能的结果） |
| `gaussdb-slowsql` / `topsql` / `sqlfetch` | 找慢 SQL、取 SQL 原文 |
| `gaussdb-explain` | 执行计划 |
| `gaussdb-sqltune` / `sqlreview` | SQL 调优、SQL 审查 |
| `gaussdb-proctune` / `procinfo` / `topproc` | 存储过程调优、过程信息 |
| `gaussdb-lockwait` / `waitevent` | 锁等待、等待事件 |
| `gaussdb-memanalyze` / `vacuum` / `wdr` | 内存分析、膨胀清理、WDR 报告 |
| `gaussdb-kb` | 知识库**查询**（runtime 镜像里只有这个） |
| `gaussdb-kb-import` / `kb-init` | 知识库**导入**与入库前标准化（只在 kb-import 镜像里） |

每个技能目录的内部结构都一样：

```
gaussdb-health/
├── SKILL.md                    给模型看的：什么时候用、怎么用、安全红线
├── scripts/                    真正干活的 Python（health.py、collectors.py、render.py…）
└── references/                 方法论、阈值表、排查手册（模型按需读取）
```

> **`SKILL.md` 是给模型看的提示词，`scripts/` 是给机器跑的代码。** 两者都要改的时候
> 特别容易只改一半 —— 脚本改了行为、提示词还在描述老行为，而没有任何测试能发现。

## `docker/` —— 镜像构建与容器行为

| 文件 | 行数 | 作用 |
|---|---|---|
| `Dockerfile` | 75 | **三阶段构建**：`base` → `runtime` / `kb-import`。构建期预置 opencode 1.18.27、rg、技能；末尾有断言卡住技能数（17 个），少一个构建就失败 |
| `Dockerfile.gateway` | 44 | 网关镜像。独立一份：它不带技能、不装 psycopg2、不要 opencode 二进制，放一起只会让用户镜像多背 100 MB。依赖只有 PyYAML，**不装 kubectl** |
| `Dockerfile.frontend` | — | 大盘前端镜像：`nginx-unprivileged` + 把 `frontend/` 拷进去，**没有构建步骤**（不装 node、不打包），21 MB |
| `nginx-dash.conf` | — | 前端的 nginx 配置：只端 `/dash/`，其余路径 404；`/healthz` 给探针；不缓存、不列目录 |
| `entrypoint.sh` | 97 | **容器启动与关闭的全过程**。顺序有意为之：目录 → 渲染配置 → `.owner` 独占 → **NAS→本地加载状态** → 库自检 → 日志清理 → `opencode serve` + 后台定期回写；收到 SIGTERM 后：WAL 合并 → **完整回写** → 退出备份 → 释放独占 |
| `podctl.py` | 419 | 启动关闭里那些**确定性动作**的实现，`entrypoint.sh` 逐条调用：渲染 opencode 配置、`.owner` 独占、库自检/恢复/checkpoint/备份、日志清理；以及 `serve-reports`——4097 报告只读端口（只 GET、只本目录、只三种后缀），大盘的数据口 |
| `statesync.py` | 236 | **本地态 ⇄ NAS 同步**。库一律用 SQLite 在线备份接口复制（不做文件拷贝）；上次非优雅退出时先给 NAS 留 `.unclean-<时间戳>` 快照再继续 |
| `opencode.jsonc.tmpl` | 17 | opencode 运行时配置的模板 |
| `tests/` | — | `test_podctl.py`、`test_statesync_units.py`、`test_image_contents_units.py`（**钉住镜像里该有哪些文件** —— 漏拷一个模块会让 Pod 起不来，而构建是成功的）、`test_nginx_conf_units.py`（前端 nginx 配置只端 `/dash/`） |

## `gateway/` —— 接入网关

**它管别人的生死，自己不按人分。** 全体共用、两副本常驻。

| 文件 | 行数 | 作用 |
|---|---|---|
| `__main__.py` | 70 | 入口（`python3 -m gateway`）。**先把配置全部校验完再碰 k8s** |
| `config.py` | 114 | 环境变量契约，**fail closed**：信任来源没配、回收模式写错、闲置时长低于下限 —— 一律拒绝启动 |
| `identity.py` | 100 | **安全边界**：凭什么相信请求头里的工号（共享密钥常数时间比较 / 来源网段），以及工号格式校验 |
| `kube.py` | 110 | k8s API 的薄封装，只用标准库 + Pod 自己的 ServiceAccount 凭据 |
| `pods.py` | 184 | 按工号建/查/删 Pod、记活动时间。口令**已存在就沿用不轮换** |
| `proxy.py` | 126 | 反向代理到 `runtime-<工号>:4096`，注入 Basic 口令，**转发字节时记活动** |
| `reaper.py` | 128 | 闲置回收。`scale`（缩到 0）或 `delete` 两种模式，都不动 NAS 数据 |
| `server.py` | 280 | HTTP 层：认完身份后按路径分三路——`/dash/*` 到大盘前端（不建 Pod、不注口令）、`/reports/*` 到用户自己容器的 4097 报告端口、其余到用户容器的 opencode；另有控制 API（`/admin/...`，给已有容器管理框架的客户）+ 不鉴权的 `/healthz` |
| `tests/` | — | 六个测试文件，其中 `test_manifest_guards_units.py` 守的是**清单**而不是代码：`enableServiceLinks` 必须关、`emptyDir` 必须有 `sizeLimit`、RBAC 不能有 `list secrets` 与 `pods/exec`、配置项必须真的能从 ConfigMap 配到、前端只能被网关访问且不能出网 |

## `frontend/` —— 四个大盘的页面

**它只是页面骨架，不碰任何人的数据。** 浏览器加载页面后，页面自己经网关向**本人的**容器取 `/reports/*`，
所以前端容器无状态、不挂 NAS、不持口令、不调 K8s。改大盘的样式、布局、加一个大盘，都只改这里；
改大盘上**显示什么数据**，要改 `agent/` 里对应技能的报告内容。

```
frontend/
├── index.html      壳：侧栏 + 主区,四个大盘共用
├── styles.css      全部样式
├── lib/            shell.js(路由与侧栏)、data.js(取报告)、charts.js(环/柱/时间线,纯 SVG)、
│                   dig.js(「深挖 →」:新标签页开一个已发出首句的对话)、fmt.js、contract.json(字段契约)
└── pages/          health.js / topsql.js / wdr.js / kb.js —— 每个大盘一个文件
```

无构建步骤，无第三方库：浏览器直接跑源码。`lib/contract.json` 列出页面用到的每个报告字段，
`agent/tests/test_frontend_contract_units.py` 用真实的技能代码生成样例报告逐一核对——
技能改了字段名，这条测试先红，而不是客户看到一块空白。

## `k8s/` —— 集群清单

```
k8s/
├── base/          基础资源（正式部署用这一套）
├── templates/     按工号渲染的 Pod 模板（网关和 provision 脚本都读它）
├── local/         Mac 本地集群专用覆盖（hostPath 当 NAS）
└── overlays/      test / prod 环境覆盖
```

### `k8s/base/`

| 文件 | 作用 |
|---|---|
| `namespace.yaml` | 命名空间 `gaussdb-agent` |
| ⚠ `nas-pv-nfs.example.yaml` | 静态 PV 样例，**NFS 地址填在这里**。复制去掉 `.example` 再填。刻意不在 kustomization 里 |
| ⚠ `nas-pvc.yaml` | 存储**申请**（500Gi RWX），地址不在它里面。只在客户自带 StorageClass 时改类名 |
| ⚠ `configmap-agent.yaml` | 用户 Pod 的配置：中间件地址、签名旋钮、工号字段、模型服务。**里面带的是示例地址，必须改** |
| ⚠ `configmap-gateway.yaml` | 网关配置：镜像标签（**升级开关**，必填）、请求头名、信任网段、回收模式与闲置时长 |
| ⚠ `configmap-agent-roles.yaml` | 角色名单（上游不传角色头时靠它判定谁是知识库管理员） |
| ⚠ `gateway.yaml` | 网关的 Deployment / Service / RBAC。RBAC 刻意收窄：secrets **没有 list**、没有 `pods/exec`。要改 `image:` 前缀 |
| ⚠ `frontend.yaml` | 大盘前端的 Deployment / Service：1 副本、非 root、只读根文件系统。要改 `image:` 前缀。**不归网关管**，升级是改这里的标签再 apply |
| ⚠ `vectordb.yaml` | 向量库 StatefulSet（openGauss 7，自带向量类型，不装插件）。要改 `image:` 前缀；没有默认 StorageClass 时要加类名 |
| ⚠ `networkpolicy.yaml` | 出入网白名单。**里面的 `10.0.0.0/8` 是占位，要改成实际地址段**；网关段的 API Server 地址也要按集群填。`frontend-policy` 那段不用改：只收网关入站、一条出网都不放 |
| `secret-*.example.yaml` | 四个 Secret 的样例（模型密钥、网关信任凭据、向量库三个口令、SM2 私钥）。**只是样例，不改、不 apply**，真实值用 `kubectl create secret` 建 |
| `kustomization.yaml` | 把上面这些串起来 |

### `k8s/templates/`

| 文件 | 作用 |
|---|---|
| ⚠ `runtime.yaml` | 普通用户的 Pod 模板。`${USER_ID}` 等占位符由网关或 `provision.py` 渲染。知识库**只读**挂载，向量库用只读库用户。**只改 `image:` 前缀，占位符不要动** |
| ⚠ `kb-import.yaml` | 知识库管理员的 Pod 模板。知识库**读写**挂载，向量库用读写库用户。同上 |

## `scripts/` —— 构建、打包、部署、验证

| 文件 | 作用 |
|---|---|
| `build-images.sh` | 构建四个镜像（runtime、kb-import、gateway、frontend）。**`--push` 有两道闸**：必须给 `--registry`；必须多架构（除非显式 `--single-arch`）—— 单架构推上去推送侧零报错，只有对面架构的客户会失败 |
| `package-images.sh` | 出**离线交付包**：五个镜像 × 两架构的 tar.gz + sha256 + k8s 清单 + 文档。`docs/plans`、`docs/security`、`docs/specs`、`docs/prototypes` 不打进去（那四处是内部件） |
| `smoke-image.sh` | 镜像冒烟：探针、登录诊断、知识库只读、`.owner` 冲突、优雅停机、损坏恢复 |
| `dash-samples.py` / `dash-preview.sh` | 大盘本地预览：用真实的技能代码生成一套样例报告，起一个本机静态服务在浏览器里看四个大盘。改页面时用 |
| `md2html.py` | 零依赖 markdown→自带样式的单个 HTML，给客户直接浏览器打开或打印 |
| `vendor-from-gh-skill.sh` | 从 gh_skill 同步技能代码到 `agent/` |
| `tcp-forward.py` | 端口转发（本地验证时把 mock 递进容器） |
| `k8s/provision.py` | **按工号建 Pod 的参考实现**。与 `gateway/pods.py` 同源，这个是给人用的（本地验证、给已有容器框架的客户参考） |
| `k8s/init-vectordb.sh` | 向量库初始化：建库、建读写与只读两个用户、自检 DataVec |
| `k8s/verify-cluster.sh` | 集群验证：隔离、无状态重建、知识库流转、只读、NetworkPolicy 生效 |
| `k8s/local-testbed.sh` | Mac 本地集群的测试床 |
| `k8s/e2e-web.sh` / `e2e-kb-init.sh` | Web 界面、知识库标准化的端到端验证 |
| `k8s/e2e-reports.sh` / `e2e-dash.sh` | 报告存档与大盘的端到端验证：一次性工号登录 → 会话里跑健康检查 → 经网关取到本人报告 → `/dash` 页面 200 |
| `k8s/auth-proxy.py` | 本地验证用的鉴权代理 |
| `k8s/local-grmp-signing.sh` | 本地签名验证 |
| `k8s/tests/` | 部署脚本的测试：打包完整性、构建推送闸、provision、shell 语法陷阱 |

## 常见问题：我要改的东西在哪

| 想做什么 | 去哪 |
|---|---|
| 改某个诊断的行为 | `agent/skills/<技能>/scripts/` —— **同时看 `SKILL.md` 要不要改**，并同步到 gh_skill |
| 改安全红线 | `agent/common/red_lines.md`（单一正文，构建期注入各 `SKILL.md`） |
| 改中间件对接 | `agent/common/grmp/` |
| 改知识库 | `agent/common/kb/` |
| 改容器启动/关闭行为 | `docker/entrypoint.sh` + `docker/podctl.py` |
| 改状态同步策略 | `docker/statesync.py` |
| 改「谁能进、进谁的容器」 | `gateway/identity.py`（安全边界，改前想清楚） |
| 改回收策略 | `gateway/reaper.py` + `k8s/base/configmap-gateway.yaml` |
| 改大盘的样式、布局，或加一个大盘 | `frontend/`（页面）。大盘上**显示的数据**来自技能报告，那要改 `agent/skills/<技能>/` 并同步更新 `frontend/lib/contract.json` |
| 加一个可配参数 | 代码里读它 **+ `k8s/base/configmap-*.yaml` 给默认值 + 网关的话还要在 `gateway.yaml` 里映射进容器** —— 漏了最后一步就是「配了没反应且不报错」，`gateway/tests` 里有守卫 |
| 换镜像版本给新用户用 | `configmap-gateway.yaml` 的 `USER_IMAGE_TAG` + 重启网关 |
| 加一份交付文档 | 放进 `docs/`（整个目录都会打进包），并在 `scripts/k8s/tests/test_package_completeness_units.py` 里加一行钉住 |

## 跑测试

```bash
python3 -m pytest -q          # 四处测试一起跑,发版前必须这样跑
```

四处分别是 `agent/tests/`（技能包）、`docker/tests/`（镜像与状态同步）、
`gateway/tests/`（网关）、`scripts/k8s/tests/`（部署脚本）。
