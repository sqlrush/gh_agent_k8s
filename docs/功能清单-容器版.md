# 功能清单（容器版）

相对非容器版（装在跳板机上、多人共用一份进程）新增的能力。
带**【实测】**的条目是在真集群上跑出来的，括号里是当时的实测值；其余为设计行为。

---

## 一、一人一容器（10 项）

| # | 能力 | 说明 |
|---|---|---|
| 1 | 每个工号一个独立容器 | 容器名按工号生成。CPU、内存、进程空间互不干扰，一个人跑长任务不影响别人 |
| 2 | 专属 NAS 目录 | 会话、历史、连接配置落在本人目录。**别人的目录不挂载** —— 不是靠权限拦，是根本看不见 |
| 3 | 状态本地化 | 容器启动时把状态从 NAS 载到本地盘，读写全在本地。NAS 抖动不会让对话卡住 |
| 4 | 定期回写 | 运行中每 60 秒把本地状态同步回 NAS（周期可配） |
| 5 | 关闭前完整同步 | 正常停止（升级、缩容、手动删）前做一次全量同步。**【实测】零丢失** |
| 6 | 异常终止留快照 | 被强杀或驱逐时，下次启动不直接覆盖：把 NAS 上那份存成 `.unclean-<时间戳>` 并告警。**【实测】真 SIGKILL 后快照与告警都出现了** |
| 7 | 对话库一致性快照 | 同步对话库用数据库的在线备份接口，不是文件拷贝 —— 拷一个正在写的库会得到一个能打开、但少了最后几轮对话的文件 |
| 8 | 同目录独占 | `.owner` 标记确保同一个人的 NAS 目录不会被两个容器同时读写（重建过程中新旧并存的那几秒） |
| 9 | 库损坏自检与恢复 | 启动时自检，损坏则从备份恢复并告知，而不是启动失败让人查日志 |
| 10 | 工作目录即项目 | 首次启动把工作目录初始化成一个版本库，Web 界面直接按项目打开 |

## 二、接入网关（11 项）

新增的网关镜像。全体共用、两副本常驻，负责「谁进来、进谁的容器」。

| # | 能力 | 说明 |
|---|---|---|
| 11 | 认上游传来的工号 | 从请求头取工号。**共享密钥 + 来源网段两道门**，任一不过直接 403 |
| 12 | 按需建容器 | 该工号没有容器就现建，等就绪再放行。**【实测】新工号首次登录 6 秒建好** |
| 13 | 反向代理并注入口令 | 用户全程不接触容器口令，也不需要知道自己在哪个容器里 |
| 14 | 口令沿用不轮换 | 已存在的口令不重新生成 —— 轮换会把正在进行的会话当场踢掉 |
| 15 | 按角色多给一个入口 | 知识库管理员额外获得一个导入容器，普通用户没有这个入口 |
| 16 | 闲置回收 | 两种模式：缩到 0 副本（**【实测】重连 7.6 秒拉起，会话完整**）或整体删除，下次登录重建 |
| 17 | 长连接不被误判闲置 | 活动时间在**转发字节时**记录，不是按请求数。模型思考几分钟不会被当成没人用 |
| 18 | 缺前置条件明确报错 | 本人令牌还没开通时回 503 并指名缺的是什么，而不是让用户等 120 秒超时 |
| 19 | 控制接口 | 列出当前容器、手动回收。密钥留空时这组接口整个关闭（连「需要鉴权」都不回） |
| 20 | 配置不全拒绝启动 | 信任来源没配、回收模式写错、闲置时长低于下限 —— 一律起不来。**配错了跑起来的网关，是一个任填工号即可进入任何人环境的接口，而从外面看它工作得很正常** |
| 21 | 升级开关 | 改一个配置值 + 重启网关 = 之后登录的人用新版本，已经在用的人不受影响 |

另有**报告存档与只读端口**（为大盘准备的数据口）：健康检查 / Top SQL / WDR / SQL 调优 / 知识库跑完把报告 JSON 存到本人 NAS 目录（每技能保留 50 份，存档失败只提示不影响报告本身）；用户容器多开一个只读端口 4097 把它端出来，只能读本人目录、只认三种后缀；另外端一份共享知识库的目录（只含案例、现行条款、已确认的关系边，不含收件目录与客户原件），供大盘知识库页签展示原文；网关按工号代理 `/reports/*`，同时为大盘前端预留 `/dash/*` 一路。

## 三、隔离与安全（6 项）

| # | 能力 | 说明 |
|---|---|---|
| 22 | 关掉集群的服务发现注入 | 默认行为会把「还有谁在用」写进每个人的环境变量里。**实测过：一个用户的容器里能看到另外两个工号** |
| 23 | 出网白名单 | 只放行中间件、模型服务（知识库索引是 NAS 上的文件，不走网络）。**【实测】未放行的地址连不上** |
| 24 | 容器自身收紧 | 只读根文件系统、非 root 运行、丢弃全部特权 |
| 25 | 网关权限最小化 | 不能进用户容器（无 exec / attach / port-forward），对口令只能按名取、**不能列举** —— 给了列举权限就等于一次请求拿到全体用户的口令 |
| 26 | 知识库读写分离 | 用户容器与池化沙箱对知识库只读挂载、只读打开索引；只有导入容器能写（含 `kb.py index` 写索引）。没有库用户与口令可泄露 |
| 27 | 安全红线随每个技能交付 | 红线正文在每个技能内部，不依赖一个集中文件被正确安装 |

## 四、知识库（5 项）

| # | 能力 | 说明 |
|---|---|---|
| 28 | 索引就是一个文件 | 向量 + 词法索引是知识库目录里的 `index/store.sqlite`（SQLite + sqlite-vec，已装进镜像）：**不用部署数据库、不用口令**。2026-10-23 起取代原 openGauss 向量库容器 |
| 29 | 向量能力可后配 | embedding 端点、模型、维度部署后再配。不配就只做词法 + 图 —— 案例检索、条款检索、关系图**全部可用**，只少语义检索 |
| 30 | 换模型必须重建 | 同维度换 embedding 模型而不重建，索引里会混着两套向量空间：相似度失去意义，而覆盖率仍显示 100%。现在直接拦住 |
| 31 | 导入与读取并发安全 | 写入互斥 + 原子写。导入容器和读取容器共享同一 NAS 目录，不会读到半个文件 |
| 32 | 出处闸门 | 现场摘录必填、引用可校验 —— 答案要能指回客户原件的哪一页 |

## 五、中间件对接（5 项，两条线都有）

| # | 能力 | 说明 |
|---|---|---|
| 33 | 显式发调用人工号 | 请求头名、报文键名都可配，两处可同时发。**取不到工号时建连接即报错，绝不发空工号** |

## 八、四个大盘（5 项）

我方第四个镜像 `gaussdb-agent-frontend`：纯静态页面，nginx 非 root 端出，21 MB。**没有新增技能**——四个大盘展示的是健康检查、Top SQL、WDR、SQL 调优、知识库这五个已有技能跑出的报告，不另算技能。

| # | 能力 | 说明 |
|---|---|---|
| 44 | 健康检查大盘 | 维度环一眼看全、越阈值发现榜、各维度卡（不可用的灰显、不进结论）、子技能状态、最近 N 次巡检与发现数趋势。**全部维度都没采到时标「采集失败」而不是「正常」**，部分没采到时注明结论不完整 |
| 45 | Top SQL 大盘 | 五个维度页签、上榜合计内占比、榜单、逐条卡；跑过调优的直接显示建议与执行计划 |
| 46 | WDR 分析大盘 | 8 项 KPI 与上一窗口对比（没有上一份就写「无对比窗口」，不造假）、DB Time 构成、一眼结论、窗口内 Top SQL / 等待 / Checkpoint / 缓存 / 文件 IO、历史窗口、原生 WDR 报告下载 |
| 47 | 知识库大盘 | 四个页签：**总览**（健康自检、缺口清单、本人近 7 天检索）；**案例**（按发生时间列出，可搜索、按系统筛选，点开看现场 / 判断 / 处置全文与依据条款）；**条款**（按规范分组，看条文、为什么、怎么判定违规、引用它的案例）；**关系图**（案例 → 现象 → 根因 → 处置 → 依据条款，点一个节点只看它那一串）。原文直接在大盘上看，不用去会话里问 |
| 48 | 按实例、按人 | 三个诊断大盘按数据库实例分开，侧栏切换；每个人只看得到自己跑出的报告——前端容器**不读任何人的数据**，页面在浏览器里经网关向用户自己的容器取报告。每条「深挖 →」在新标签页打开一个已发出首句的对话，首句里写明先登录哪个库。中间件地址与内部接口路径在存档时就隐去，不会出现在大盘上 |

大盘展示的是**这个人跑过的报告**，不是系统替他采的数据：没有采集器、没有定时器，不会在用户不知情时替他跑技能。要「自动更新」需要另加调度，本版没有。

## 九、池化沙箱（第二种部署形态，6 项，v1.2.0）

由贵方平台维护一池预先启动的沙箱：登录时分配、退出时回收。详见《池化接入手册》。

| # | 能力 | 说明 |
|---|---|---|
| 49 | 预热池 | 平台预建 N 个沙箱，登录即分配；超出时现建。**【实测】16 个沙箱 6～7 秒全部就绪；登录约 2 秒；现建再绑定约 5～6 秒** |
| 50 | 绑定 / 解绑 | 三个控制接口（bind / unbind / status），返回码按「平台该怎么做」设计；同一个人同一时刻只能占一个沙箱，冲突时回 409 并给出持有者与等待秒数 |
| 51 | 跨沙箱接续 | 退出时完整写回 NAS，下次登录分到另一个沙箱也能看到并接着聊。**【实测】退出再登录后模型记得上一句** |
| 52 | 用完即换 | 一个沙箱一生只服务一个人，退役后删除、补建新的——前一个人的文件与后台进程不可能留给下一个人 |
| 53 | 模型看不到别人的目录 | 读写 NAS 的是只跑我方代码的副容器，跑模型的主容器只挂共享知识库；搬运时不跟随任何链接。**【实测】埋的三种链接一条都没被搬上 NAS；主容器拿不到控制密钥与集群凭据** |
| 54 | 入站只放行平台 | 沙箱的三个端口只对带平台标签的来源开放，沙箱之间互相到不了。**【实测】** |

同时进入两种形态的改进：**对话库没变就不回写**（原来每 60 秒整库复制一遍，历史大了会把 NAS 写满）；
状态搬运**不再跟随符号链接**。

## 十、诊断能力（v1.3.0 新增，9 项，两条线都有）

这一版的诊断改动在非容器版（gh_skill）与容器版是同一份代码。白名单相对上一版**新增 13 条、更新 9 条**（全部只读）。

| # | 能力 | 说明 |
|---|---|---|
| 55 | 时间段的 Top SQL | 「最近 30 分钟」「10:46 到 11:07」都能问。取包住这段时间的 WDR 快照 / 自留采样 / 此刻两端相减，**不追求精确，只保证覆盖住**，并在答案开头写明要的是哪段、实际评估的是哪段、为什么；跨过实例重启时只覆盖重启之后那段并明说。**【实测】og5 故障时段与 WDR 逐条一致** |
| 56 | 时段体检 | 健康检查按时间段看：负载、事务与死锁、IO / 临时溢出 / 检查点、等待分布、时段 Top SQL 两端相减；连接、锁、长事务、膨胀、复制这类瞬时状态**逐项写明回看不了**，不拿此刻的值顶替；终点是此刻时给当前值并标明。临时溢出归到具体语句。**【实测】DB time、死锁 24 次、溢出 7.8G、锁等待与 WDR 一致** |
| 57 | 死锁日志解析 | 死锁明细数据库里不留（只有次数）。用户把日志里 `deadlock detected` 那几段贴进对话，解析出环、各自的语句、谁被牺牲，按模式归类给出改法（统一加锁顺序、一次锁住要改的行、应用捕获 40P01 重试整个事务）。不依赖日志前缀、贴乱了换行也能解析、不连库。**【实测】一份真实日志 27 次死锁全部解析，牺牲者 27/27 与日志一致** |
| 58 | 参数体检 | 新技能 `gaussdb-config`：只报客观错误——参数自相矛盾、会静默丢数据的危险配置、按实例内存预算算出的超卖；**不给凭空的推荐值** |
| 59 | 健康检查补六项 | 事务号冻结水位、库与表空间占用量、同步提交与部署形态（单机不误报）、WAL 复制槽、线程池用量、分区数 |
| 60 | 膨胀估算 | 回答「空间比应占多了多少」（死元组比例回答的是「有多少可回收」），VACUUM 不还盘时据此评估重建 |
| 61 | WDR 取数修正 | 修正 DB time 少报（实测少报约 8800 倍）、Top SQL / 文件 IO 漏掉窗口内新出现的对象（文件 IO 实测 1468 个文件只统计到 185 个）；各维度元凶从耗时前 200 条里找，**榜外的溢出冠军也会列出来**，临时溢出写明归到哪条语句 |
| 62 | 不把噪声判成告警 | 窗口几乎空闲时不判任何比例；等待占比与 DB time 自相矛盾（部分之和超过整体）时明说「不可信」、不判告警。**【实测】空闲库上原来 5 个小时窗口各报一条 🟠，现在零误报** |
| 63 | 大盘显示时段报告 | 时段榜、时段体检从对话里的链接直接打开那一份；按评估窗口筛选；默认页仍是最近一次此刻巡检；回看不了的维度标「回看不了」，不标「采集失败」 |

## 需要如实说明的三条

**一、能看到哪些数据库，仍由中间件决定。**
我方按工号隔离的是容器、会话、历史、知识库这些「本人的东西」。
至于某个工号能诊断哪些实例，取决于中间件按人签发的令牌以及它背后的账号映射 ——
那一段不在我方。工号已经会发给中间件，中间件如何使用需贵方确认。

**二、鲲鹏镜像未在真实硬件上验证过。**
arm64 镜像构建完成并可载入，但没有在鲲鹏服务器上跑过一次完整会话。
上线前建议留出一次冒烟的时间。

**三、异常终止会丢一个同步周期。**
默认 60 秒。正常停止是零丢失；被强杀或节点驱逐时，最后不到一分钟的对话会丢，
下次启动会明确告警并留下当时的快照。这是权衡后接受的代价 —— 缩短周期会增加 NAS 写入量。
