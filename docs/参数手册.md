# 参数手册

全部可配参数、含义、默认值、配错了会怎样。

**参数分四处**：

| 处 | 对象 | 改了要做什么 |
|---|---|---|
| ① | ConfigMap `agent-config` | 重建用户 Pod 后生效 |
| ② | ConfigMap `gateway-config` | 重启网关后生效 |
| ③ | 三个 Secret（固定池化另加一个） | 重启相应 Pod 后生效；固定池化的池子 Pod 要逐个删掉重建 |
| ④ | NAS 上的 `kb/kb.yaml` | 下次调用即生效（不用重启） |

> **凡是标「无默认值」的都必须填**，缺了对应组件会拒绝启动。
> 这是刻意的：带着不完整的配置跑起来，问题会在几周后以别的形态暴露。

## ① `agent-config` —— 用户 Pod 的配置

```bash
kubectl -n gaussdb-agent edit configmap agent-config
```

### 中间件

| 参数 | 清单里带的值 | 说明 |
|---|---|---|
| `GRMP_API_HOST` | `grmp.example.internal`（示例） | 中间件主机名或 IP |
| `GRMP_API_PORT` | `8080` | 中间件端口 |
| `GRMP_PATH_PREFIX` | 空（**必填**） | 中间件接口路径前缀，**必填**，中间件团队提供（以 `/` 开头、只写路径、末尾不带 `/`，形如 `/xxx/grmp/diagnostic/agent`）；没填时登录数据库直接报「GRMP_PATH_PREFIX 没配」 |

> **这一节和下面模型服务那一节的四个值，清单里带的是示例地址，必须改。**
> 不改不会报「缺少配置」—— 值是有的，只是指向一个不存在的主机，
> 表现为第一次对话卡住后超时。部署完先按 §验证 里那两条自检，别等用户来报。

### 中间件签名（客户 2026-09 起的加固要求）

| 参数 | 默认值 | 可选值 | 说明 |
|---|---|---|---|
| `GRMP_APPKEY` | 空 | | 调用方应用名，整个智能体一个。**空 = 完全不发签名相关的头**（中间件还没开校验时用） |
| `GRMP_SIGN_MODE` | `full` | `full` / `headers-only` | `full` 发三个头（Appkey + Timestamp + Signature），需要私钥；`headers-only` 只发前两个，不需要私钥 |
| `GRMP_SIGN_TIMESTAMP` | `ms` | `ms` / `s` | 时间戳单位。`s` 输出 10 位（如 `1758431954`），`ms` 输出 13 位 |
| `GRMP_SIGN_FORMAT` | `raw` | `raw` / `der` | 签名编码结构。`raw` = r‖s 共 64 字节；`der` = ASN.1（Java BouncyCastle 默认） |
| `GRMP_SIGN_ENCODING` | `hex` | `hex` / `base64` | 签名的文本编码 |
| `GRMP_SIGN_USER_ID` | `1234567812345678` | 任意字符串 | SM2 签名的 userId。**国标默认是这一串，而 OpenSSL 默认是空串** —— 中间件用哪个必须问清，填错会一律验签失败 |
| `GRMP_SIGN_PAYLOAD` | `{path}+{timestamp}` | 只认这两个占位符 | 签名原文的拼法 |

> **`GRMP_SIGN_MODE` 的三种组合**
>
> | `GRMP_APPKEY` | `GRMP_SIGN_MODE` | 实际发出的头 | 需要私钥 |
> |---|---|---|---|
> | 空 | 任意 | 只有 `auth` | 否 |
> | 有值 | `headers-only` | `auth` + `Appkey` + `Timestamp` | **否** |
> | 有值 | `full` | 四个全发 | **是** |
>
> **拿不到私钥时不会自动降级。** 配了 `full` 却没有私钥会直接报错并提示改用 `headers-only` ——
> 自动降级会让生产上 Secret 挂载失败时「全签」悄悄变成「不签名」。

### 把调用人工号发给中间件

| 参数 | 默认值 | 说明 |
|---|---|---|
| `GRMP_USER_ID_HEADER` | 空 | 工号放在哪个请求头里（如 `X-User-Id`） |
| `GRMP_USER_ID_PARAM` | 空 | 工号放在报文顶层的哪个键里（如 `userId`） |

两个都留空 = 不发工号。字段名以中间件口径为准，两处可同时配。

### 实例别名（让智能体认得「og5」这类叫法）

| 参数 | 默认值 | 说明 |
|---|---|---|
| `GRMP_INSTANCE_ALIASES` | 空 | 每项 `别名=实例IP/库名  # 说明`，换行或分号分隔，例如 `核心库=10.1.2.3/coredb  # 生产核心`。别名只能用字母、数字、`._-` |

api 模式没有预置的连接清单，用户说「核心库」时智能体只能反问是哪个库。登记之后，智能体 `login --list` 能看到
**别名、库名与说明（不显示实例 IP）**，用 `--alias` 登录。登录照样只属于当前对话、每次重新登录。
写错的项不影响 Pod 启动，会在 `login --list` 里列出来提示修正；改了要重启用户容器（或等它下次拉起）才生效。
取值来自 `GSDB_USER_ID`。**填了字段名而取不到工号时建连接即报错，绝不发空工号。**

### 模型服务

| 参数 | 清单里带的值 | 说明 |
|---|---|---|
| `MODEL_BASE_URL` | `http://llm.example.internal/v1`（示例） | OpenAI 兼容地址，**必须含 `/v1`** |
| `MODEL_ID` | `qwen3-32b`（示例） | 模型 id |
| `MODEL_PROVIDER_NAME` | `model-service` | 对话界面里显示的服务名，可不改 |
| `MODEL_INPUT_MODALITIES` | 空（纯文本） | 模型能接收的输入，逗号分隔，如 `text,image`。**知识库导入要读照片 / 截图时必须含 `image`** |

前三项**留空**（不是填错）时 Pod 直接起不来并指名缺哪个 —— 密钥从 Secret 来，
地址与模型名从这里来，缺一样都没法生成对话配置。

`MODEL_INPUT_MODALITIES` 留空时，opencode 把模型当纯文本模型：管理员让模型看照片，read 当场报
「this model does not support image input」，图片根本没发给模型。模型服务支持图片时改成 `text,image`，
改完重启导入容器（`kubectl -n <命名空间> rollout restart deploy/kb-import-<工号>`，或等它闲置回收后再进）。
模型服务不支持图片却设了 `image`：配置能生成，但发图那一轮模型服务会报错，请先向模型服务方确认。
可选项 `text` / `image` / `audio` / `video` / `pdf`，写错（如 `images`）Pod 启动即失败并列出可选项。

手机直出的 HEIC 与扫描件常见的 TIFF，导入镜像会自动转成 jpg 副本再给模型看（不改原件），平台不用配置。

### 验证这两节配对了

```bash
S=<某个已开通的工号>
kubectl -n gaussdb-agent exec deploy/runtime-$S -- \
  curl -s -o /dev/null -w "模型服务 %{http_code}\n" $MODEL_BASE_URL/models
kubectl -n gaussdb-agent exec deploy/runtime-$S -- \
  sh -c 'curl -s -o /dev/null -w "中间件 %{http_code}\n" http://$GRMP_API_HOST:$GRMP_API_PORT/'
```

两行都要有 HTTP 状态码（`401` / `404` 也算通 —— 说明网络到得了）。
出现 `000` 就是地址不对或被网络策略挡住，**这时候用户那边看不出任何异常，直到他发第一句话。**

### 网页剪藏（知识库导入，v1.4.1 起）

需要登录的内网网页（Wiki / Confluence / 门户），由知识库管理员在**已登录的浏览器**里点书签「导入知识库」剪藏进来：
页面内容只经管理员的浏览器进来，导入容器不访问任何内网网站，出网策略不用改。

| 参数 | 清单里带的值 | 说明 |
|---|---|---|
| `KB_CLIP_ORIGINS` | 空（关闭） | 允许剪藏的内网网站，每项写「协议://主机[:端口]」，逗号分隔，如 `https://wiki.内网,https://confluence.内网:8090`。**不带路径** |
| `KB_CLIP_MAX_MB` | `30` | 单次剪藏（网页 + 页内图片）总大小上限，单位 MB，最大 `45` |

两项都在 `agent-config` 里**只配一处**：网关读它（剪藏页只收名单里的网站交来的内容），导入容器也读它（`kb.py clip status`
据此告诉管理员开没开、某个链接在不在名单里）。改完 `kubectl -n <命名空间> rollout restart deploy/gateway`；
导入容器下次进入时生效（或 `rollout restart deploy/kb-import-<工号>`）。写错格式（缺 `https://`、带了路径）网关拒绝启动，
日志里写明是哪一项 —— 宁可起不来，也不要悄悄少收一个网站。

管理员第一次用时，导入环境里的模型会一步一步带着装书签（安装页 `/kb-import/clip/install`）；书签用不了时，
浏览器「另存为 → 网页，单个文件（.mhtml）」后拖进剪藏页 `/kb-import/clip`，效果相同。
剪藏只对知识库管理员开放（与 `/kb-import` 同一套身份校验）。

## ② `gateway-config` —— 接入网关的配置

```bash
kubectl -n gaussdb-agent edit configmap gateway-config
```

> **下面的名字是 ConfigMap 里的键名**，容器里对应的环境变量多一个 `GATEWAY_` 前缀
> （`USER_IMAGE_TAG` → `GATEWAY_IMAGE_TAG`）。改 ConfigMap 用键名即可。

### 用户 Pod 的镜像

| 参数 | 默认值 | 说明 |
|---|---|---|
| `USER_IMAGE_REGISTRY` | 空 | 用户 Pod 镜像的仓库前缀，例如 `registry.example/gaussdb-agent`，网关据此建 `<前缀>/gaussdb-agent-runtime:<USER_IMAGE_TAG>`。**镜像推在镜像仓库里时必须填**：留空时镜像名不带前缀，节点会去 docker.io 拉，用户一登录就 `ImagePullBackOff`（504）。只有镜像直接载在每个节点上（`kind load` / `docker load`）时才留空。只写前缀，不带 `http://` |
| `USER_IMAGE_TAG` | **无默认值** | 给用户 Pod 用哪个版本的镜像。**这是升级开关**：改它 + 重启网关 = 之后登录的人用新版，已在用的人不受影响。刻意不给默认值 —— 默认成 `latest` 会让升级悄悄发生在某个人下次登录时 |
| `PULL_POLICY` | `IfNotPresent` | |
| `FRONTEND_SERVICE` | `frontend` | 大盘前端的 Service 名，`/dash/*` 代理到它。没部署前端镜像时这条路回 502「大盘服务未部署或不可达」，**不影响对话与报告** |

### 身份

| 参数 | 默认值 | 说明 |
|---|---|---|
| `USER_HEADER` | `X-Agent-User` | 上游 SSO 把工号放在哪个请求头里 |
| `ROLES_HEADER` | `X-Agent-Roles` | 角色/组，逗号分隔。另外，工号登记在 ConfigMap `agent-roles`（`kb-admins`，每行一个）里的人也算知识库管理员——SSO 不传角色时用它；两者满足一个即可，网关每 30 秒重读一次那张表 |
| `KB_ADMIN_ROLES` | `kb-admin` | 哪些角色值算知识库管理员（会多建一个 kb-import Pod）。逗号分隔，大小写不敏感 |
| `TRUST_CIDRS` | 空 | 允许携带工号头的来源网段，逗号分隔 |

> **`TRUST_CIDRS` 与 Secret 里的 `TRUST_SECRET` 至少要有一个。** 两个都空时网关**拒绝启动** ——
> 不限制来源等于「任填工号即可进入任何人的环境」，而且从外面看它工作得好好的。

### 回收

| 参数 | 默认值 | 下限 | 说明 |
|---|---|---|---|
| `REAP_MODE` | `scale` | | `scale` 缩到 0 副本（重连 7 秒拉起）；`delete` 删闲置的那个容器的 Deployment/Service（口令与 GRMP 令牌 Secret 保留，下次登录重建）。**两种都不动 NAS 数据** |
| `IDLE_SECONDS` | `1800` | **300** | 闲置多久回收。低于下限拒绝启动 —— 模型跑长任务时几分钟没有流量是正常的，配太短会在用户等结果时收掉 Pod |
| `SWEEP_SECONDS` | `120` | 10 | 回收器多久扫一遍 |
| `ACTIVITY_INTERVAL_SECONDS` | `60` | 5 | 活动时间的写入节流。调小会显著增加对 API Server 的写入量 |
| `READY_TIMEOUT_SECONDS` | `120` | 10 | 等新 Pod 就绪的上限。超时用户看到 504（括号里带原因类别）；拉不到镜像、配置缺失、个人目录初始化失败这三类等下去不会好，网关不等满上限，当场回 503 |

> 低于下限一律**拒绝启动**，不会退回默认值 —— 运维以为自己调小了，实际跑的是默认值，
> 这种「配了没生效」比起不来难查得多。

### 诊断容器怎么来（按需 / 固定池化）

| 参数 | 默认值 | 说明 |
|---|---|---|
| `RUNTIME_MODE` | `ondemand` | `ondemand` 按人现建 Pod；`pool` 固定池化（先按《固定池化手册》部署池子）。知识库管理员的导入容器两种模式下都按需建 |
| `POOL_SELECTOR` `POOL_IDLE_SECONDS` `POOL_EARLY_IDLE_SECONDS` `POOL_RETAIN_DAYS` `POOL_FREE_SLOTS` `POOL_SWEEP_SECONDS` `POOL_WAIT_SECONDS` | 见手册 | 只在 `RUNTIME_MODE=pool` 时生效：闲置多久转保留、满员时可提前转保留的闲置时长、保留几天、每 Pod 留几个空位、清扫周期、一次请求最多等多久。默认值、下限与含义见《固定池化手册》§4.2 |

### 其它

| 参数 | 默认值 | 说明 |
|---|---|---|
| `GATEWAY_NAMESPACE` | **无默认值** | 网关在哪个命名空间里建 Pod。**在 Deployment 里直接写死**为 `gaussdb-agent`，不在 ConfigMap 里 |
| 监听端口 | `8080` | **不通过 ConfigMap 配**。改它要同步改 Deployment 的 `containerPort` 与 Service 的 `targetPort`，不是「配一下」的事。变量名是 `GATEWAY_LISTEN_PORT`，**刻意不叫 `GATEWAY_PORT`** —— 那个名字会与 K8s 自动注入的 Service 发现变量撞名 |

## ③ 三个 Secret

**都不要写进清单或脚本。** 样例见 `k8s/base/*.example.yaml`。

**注入到哪个容器**（2026-10-23 起）：模型 Key、GRMP 令牌、SM2 私钥只注入**凭据代理**——按需模式是用户 Pod 里的 `credproxy` 容器，
固定池化是池子 Pod 的管家；opencode 所在的容器（模型在那里执行命令）一样都没有。凭据由代理在转发时加上，见 `docs/env-contract.md`「凭据代理」。

### `model-api`

| 键 | 说明 |
|---|---|
| `MODEL_API_KEY` | 模型服务密钥 |

### `gateway-auth`

| 键 | 默认 | 说明 |
|---|---|---|
| `TRUST_SECRET` | 无 | 与上游 SSO 约定的共享密钥，**至少 16 字符**。上游在 `X-Agent-Trust` 头里带上。轮换时必须与上游同时改，否则所有用户会在改完那一刻全部 403 |
| `ADMIN_TOKEN` | 空 | 控制 API（`/admin/...`）的密钥。**留空 = 控制 API 整个关闭**，连「需要鉴权」都不回，直接 404 |

### `grmp-token-<工号>`（每人一个）

| 键 | 说明 |
|---|---|
| `GRMP_AUTH_TOKEN` | 该用户本人的中间件令牌，由客户中间件按人签发 |

**网关不创建它** —— 令牌按人签发，网关无从得知。缺它时用户看到 503「您的环境尚未开通」，
网关日志里写明缺的是哪个 Secret。**开通一个用户 = 创建这个 Secret。**

### `grmp-sm2`（可选，全体共用）

| 键 | 说明 |
|---|---|
| `GRMP_SM2_PRIVATE_KEY` | 该 Appkey 的 SM2 私钥（64 位 hex 或 PEM），客户签发 |

只在 `GRMP_APPKEY` 非空且 `GRMP_SIGN_MODE=full` 时需要。模板里是 `optional: true`，没建时 Pod 照常启动。

### 固定池化另需的一个（见《固定池化手册》）

| Secret | 键 | 说明 |
|---|---|---|
| `sandbox-control` | `KEY` | 网关与各 Pod 的管家共用的控制密钥：网关调管家 4098 接口时给请求签名、给 GRMP 令牌加密，管家验签、解密、给应答签名。**至少 16 字符**，只注入网关与管家，槽位里没有；池化模式下缺了网关与管家都拒绝启动。轮换：改 Secret → 重启网关 → 逐个删池子 Pod |

固定池化仍是每人一个 `grmp-token-<工号>`（与按需模式相同），每次绑定 / 恢复时由网关读出、加密交给管家；
管家只在这个槽位在用期间用它转发中间件请求，令牌不下发到槽位。

## ④ `kb/kb.yaml` —— 知识库配置

位置：NAS 的 `kb/kb.yaml`，**全体共用一份**。改完下次调用即生效，不用重启。

### 完全不配（无语义检索）

不存在这个文件，或者只写一行：

```yaml
embeddings: {source: none}
```

案例检索、条款检索、关系图**全部可用**，只是没有语义检索（换个说法找不到）。

### 配上 embedding（语义检索）

```yaml
embeddings: {source: url, base_url: http://<embedding端点>/v1, model: bge-m3, dims: 1024}
```

**向量库不用配。** 向量 + 词法索引是知识库目录里的 `kb/index/store.sqlite`（SQLite + sqlite-vec），位置固定、没有口令，
由导入容器的 `kb.py index` 建与更新，runtime 与固定池化的槽位只读打开（见《部署手册》阶段 5）。
旧版本的 `store.pg` 段已不再使用：留着不报错，`kb.py index` / `kb.py health` 会提示可以删。

| 参数 | 默认值 | 说明 |
|---|---|---|
| `embeddings.source` | `none` | `none` / `url` / `opencode`。`opencode` 复用对话模型的端点（经凭据代理，Key 由代理加；模型服务本身要有 `/embeddings`，DeepSeek 等纯聊天 API 没有，回 404，这时用 `url`） |
| `embeddings.base_url` | 空 | `source: url` 时必填，**要含 `/v1`** |
| `embeddings.model` | `bge-m3` | embedding 模型名 |
| `embeddings.dims` | `1024` | 向量维度，**必须与模型实际输出一致**。不一致时每批都失败，索引输出里会显示 `失败 N` |
| `embeddings.timeout_s` | `30` | 索引时单批超时 |
| `embeddings.query_timeout_s` | `1.5` | 查询时超时。超了本次不用向量，不影响返回。**嵌入服务是 Ollama 时**：模型闲置 5 分钟被卸载，再加载实测 1.1–1.4 秒，贴着这个超时 —— 设 `OLLAMA_KEEP_ALIVE=-1` 或把这里放宽到 `3` |
| `embeddings.batch` | `16` | 每批多少条 |
| `store.graph` | 不配 | Neo4j 地址。**不配没有任何损失** —— 自动退回读 `graph/*.yaml`，答案一样。几千条边内文件遍历毫秒级 |

> **已有知识库后配上 embedding**：改好 `kb.yaml` 后在导入容器里再跑一次 `kb.py index`，已有的块会补上向量（v1.4.0 起；之前要加 `--fill-missing`）。
>
> **换 embedding 模型必须 `index --rebuild`。** 同维度换模型而不重建，索引里会混着两套向量空间，
> 相似度失去意义而覆盖率仍显示 100%。已加闸门：换了模型不重建直接拒绝并说明。

## 平台注入、不要手工改的

这些由清单模板或 entrypoint 自动设置：

| 参数 | 值 | 说明 |
|---|---|---|
| `GSDB_USER_ID` | 工号 | 模板按 Pod 注入。报告落款与发给中间件的工号都取自它 |

| `OPENCODE_PORT` | `4096` | |

**工具权限**（`podctl` 渲染进 `opencode.json`，opencode 真正执行；技能包 AGENTS.md 里那段 permission 只是提示词）：

| 工具 | runtime | kb-import |
|---|---|---|
| 编辑 / 写文件 | 拒绝 | 放行（`gaussdb-kb-init` 写草稿） |
| 联网（webfetch / websearch） | 拒绝 | 拒绝 |
| 技能 | 只 `gaussdb-*` | 只 `gaussdb-*` |
| 读文件 / 搜索 / 列目录 | 放行 | 放行 |
| 命令行 | 只放行 `python3` 执行技能目录里 `gaussdb-*` 的脚本与只读命令（`cat` `grep` `head` `tail` `ls` `find` `cd` `stat` `wc` `sort` 等，`find` 不许 `-exec` / `-delete`）；这些命令可以带 `2>/dev/null` / `2>&1` / `>/dev/null`；写文件的重定向、跳出技能目录、`/proc`、`env` / `printenv` / `set` 一律拒绝（`export` / `declare` 见下） | 同左 |

已知管不到的：`export`、`declare -p` 这类声明命令 opencode 不核对，能打印环境 —— 所以环境里不放凭据（凭据代理）。
核对方法：`scripts/check-opencode-permissions.py --image <镜像>`（真 opencode + 假模型逐条发工具调用）。

**固定池化的池子**（`k8s/tools/render-pool.py` 渲染）另有：

| 参数 | 值 | 说明 |
|---|---|---|
| `POOL_MODE` | `slot` / `steward` | 槽位容器 / 管家容器；入口据此把 1 号进程交给槽位守护进程（先清盘）或管家 |
| `SLOT_INDEX` | 0 … 槽位数-1 | 槽位用：决定端口（对话 4100+10i、报告 4101+10i、模型中继 4102+10i） |
| `SLOTS_PER_POD` / `POD_NAME` | 渲染时定 / k8s 注入 | 管家用；`POD_NAME/槽位号` 是 NAS 上独占标记的持有者 |
| `GSDB_USER_ID` / `OPENCODE_SERVER_PASSWORD` / `REPORTS_TOKEN` | 绑定时才有 | **不在清单里**：工号、每次换新的口令与报告令牌由管家按次下发 |
| `MODEL_API_KEY` / `GRMP_SM2_PRIVATE_KEY` | 管家 | 只注入管家（凭据代理），槽位里没有；本人的 GRMP 令牌也只在管家 |

## 最小可用配置

只想尽快跑起来的话，下面这些是**必须**的，其余全用默认值：

```yaml
# agent-config
GRMP_API_HOST: "<中间件地址>"
MODEL_BASE_URL: "<模型服务地址,含/v1>"
MODEL_ID: "<模型名>"

# gateway-config
USER_IMAGE_TAG: "agent-v1.4.2-oc1.18.27"

# Secret model-api
MODEL_API_KEY: "<模型密钥>"

# Secret gateway-auth
TRUST_SECRET: "<至少16字符的随机串>"

# Secret grmp-token-<工号>（每个使用者一个）
GRMP_AUTH_TOKEN: "<该用户的中间件令牌>"
```

`kb.yaml` 不配 → 知识库没有语义检索（关键词检索与关系图照常）。
`GRMP_APPKEY` 不配 → 不发签名头。
`grmp-sm2` 不建 → 不影响启动。
