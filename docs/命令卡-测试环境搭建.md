命令里凡是出现 `①`、`②`…… 的地方，**连同后面的中文一起删掉，换成第 0 步表格里填的值**。

举例：表格 ① 填的是 `zhangsan`，那么

```bash

```

**不要**保留 `①`，也不要保留中文说明。

## 第 1 步：生成 GitHub 令牌

> **前提**：已收到我方「已开通」的回复。没收到就先等 —— 令牌生成了也拉不到镜像。

1. 浏览器打开 https://github.com/settings/tokens/new
2. **Note** 填：`gaussdb-agent`
3. **Expiration** 选：`90 days`
4. 往下找到 **`write:packages`** 那一行，**勾选它下面一行的 `read:packages`**
   （**只勾这一个**。不要勾 `repo`，也不要勾 `write:packages`，源码是公开的不需要权限）
5. 拉到最底下点绿色的 **Generate token**
6. 页面顶部会出现一串 `ghp_` 开头的字符——**立刻复制，关掉页面就再也看不到了**
7. 把它填进第 0 步表格的 ②

## 第 3 步 🙋：确认集群能不能用（**这一步找 K8s 管理员**）

把下面三条发给 K8s 管理员，请他确认并把结果告诉你：

```bash
kubectl auth can-i create deployment -n gaussdb-agent
kubectl auth can-i create networkpolicy -n gaussdb-agent
kubectl get storageclass
```

**需要他确认三件事**：

1. 前两条都返回 `yes`
2. **集群的节点能挂载贵方的 NFS 服务器**（第 6 步会把 NFS 地址填进去；不需要事先有 StorageClass）
3. **集群的网络插件支持 NetworkPolicy**（常见的 Calico、Cilium 支持；Flannel 默认不支持）

**第 3 条尤其重要**。不支持的话用户之间的网络隔离不生效，这是个安全问题——
请他明确答复支持或不支持，**不要猜**。

## 第 6 步 🙋：准备存储（**这一步找存储管理员**）

把下面这段发给存储管理员：

> 请在 NFS 服务器上创建以下目录，并把属主设为 uid 1000：
>
> ```bash
> mkdir -p /export/gaussdb-agent/users
> mkdir -p /export/gaussdb-agent/admins
> mkdir -p /export/gaussdb-agent/kb
> chown -R 1000:1000 /export/gaussdb-agent
> chmod -R 775 /export/gaussdb-agent
> ```
>
> 并请告知：NFS 服务器地址、导出路径、是否为 NFS v4.1。

拿到地址后，填进第 0 步的 ④⑤。然后把我方给的存储样例复制一份，填上地址：

```bash
cp k8s/base/nas-pv-nfs.example.yaml k8s/base/nas-pv-nfs.yaml
vi k8s/base/nas-pv-nfs.yaml
```

只改**最后两行**，把尖括号连同里面的字一起换掉：

```yaml
  nfs:
    server: ④NFS服务器地址
    path: ⑤NFS导出路径
```

> 文件里其它行**一行都不要动**。尤其 `local_lock=all` 和 `Retain` 这两处，
> 前者少了数据库文件会出问题，后者改了会在删除时把用户数据一起删掉。

（`vi` 用法：按 `i` 进入编辑，改完按 `Esc`，再输入 `:wq` 回车保存退出。）

改完先把这一个文件交给集群：

```bash
kubectl apply -f k8s/base/nas-pv-nfs.yaml
```

**你应该看到**：`persistentvolume/nas-nfs created`

> `nas-pvc.yaml` 那个文件**不用改**。它只是「申请一块存储」，地址不在它里面。

```bash
sed -i "s#image: gaussdb-agent-#image: $REG/gaussdb-agent-#" k8s/base/gateway.yaml k8s/base/frontend.yaml k8s/templates/runtime.yaml k8s/templates/kb-import.yaml

```

### 验收 1：网关活着

```bash
curl -s http://127.0.0.1:18080/healthz
```

✅ **应该看到**：`{"ok": true, "version": "gaussdb-agent-gateway"}`

### 验收 2：没有凭据的人进不来


### 验收 3：有凭据的人能进来，且环境自动创建

## 附：清理重来

装坏了想从头再来（**不会删掉已有数据**）：

```bash
kubectl delete namespace gaussdb-agent
```

等它删完（可能要 1–2 分钟），**再执行这一条解除存储卷的旧绑定**(命名空间删掉后存储卷申请已经没了,直接解除即可):

```bash
kubectl patch pv nas-nfs --type json -p '[{"op":"remove","path":"/spec/claimRef"}]'
```

> **已经重装过、PVC 卡在 `Pending` 了?** 顺序不能换:先删用户容器与 PVC,再解除,再重建 PVC ——
> 只做解除的话,之前失败过的 PVC 会越来越晚才重试,要等好几分钟甚至更久:
>
> ```bash
> kubectl -n gaussdb-agent delete deploy,svc -l app=gaussdb-agent
> kubectl -n gaussdb-agent delete pvc nas
> kubectl patch pv nas-nfs --type json -p '[{"op":"remove","path":"/spec/claimRef"}]'
> kubectl apply -f k8s/base/nas-pvc.yaml
> ```

> **这一步不能省。** 删命名空间时存储卷申请跟着被删，而存储卷本身按设计是「保留」模式（数据都在），
> 它会变成 `Released` 状态、仍记着旧申请。不解除，重新创建的申请永远绑不上，
> 所有用户容器都卡在 `Pending`，Events 里是 `pod has unbound immediate PersistentVolumeClaims`。
> 如果用的是贵方自带的存储类（没有 `nas-nfs` 这个 PV），跳过这一步。

然后从**第 8 步**重新开始。
镜像不用重新下载。
