# 对接清单：SSO、NAS、K8s 都已具备时，各方要做什么

**适用前提**：贵方已有统一认证（SSO）、已有 NAS、已有 K8s 集群。
本篇按**团队**分节，每节是「要做的事 + 我方给的接口 + 怎么验」，每节都可以单独转发给对应团队。

架构与设计原理见 `接入手册-SSO与K8s.md`；参数逐项说明见 `参数手册.md`；
逐条命令见 `部署手册-从零到上线.md`。本篇不重复这些内容。

---

## 0. 一页看清

| 提供方 | 提供什么 | 本篇对应章节 |
|---|---|---|
| 统一认证团队 | 认完人，把工号放进一个请求头转发过来 | §1 |
| 存储团队 | 一个 NFS 导出目录，三个子目录 | §2 |
| 容器平台团队 | 一个命名空间、镜像仓库、支持网络策略的 CNI | §3 |
| 中间件团队 | 按人签发的令牌；确认工号字段名 | §4 |
| AI 平台团队 | 模型服务地址与密钥；embedding 端点（可选） | §5 |
| 我方 | 五个镜像、集群清单、接入网关、四个大盘、部署与运维手册 | — |

**整条链路**：

```
用户浏览器
  └─ 贵方统一认证（认人）
       └─ 贵方反向代理 / Ingress（加上工号头 + 信任凭据）
            └─ 我方接入网关（认工号 → 建/找容器 → 代理过去）
                 └─ 该用户的专属容器
                      ├─ 贵方中间件 ── 目标数据库
                      ├─ 贵方模型服务
                      └─ 知识库（NAS + 向量库）
```

**贵方只需要把流量送到接入网关这一个入口**，容器的创建、调度、回收由网关负责，
不需要贵方的认证系统去调用任何容器管理接口。

## 1. 给统一认证团队

### 1.1 我方需要的只有一样

认证成功后，把该用户的**工号**放进一个请求头，转发给接入网关。就这一件事。

| 请求头 | 必需 | 内容 |
|---|---|---|
| `X-Agent-User` | **是** | 工号 |
| `X-Agent-Trust` | 是（或用网段，见 §1.2） | 我方给出的一串固定密钥 |
| `X-Agent-Roles` | 否 | 该用户的角色/组，逗号分隔 |

头名都可改，改在我方配置里，贵方按实际现状告诉我方即可。

**我方不需要**：不需要令牌校验回调、不需要用户列表同步、不需要贵方调用任何创建接口、
不需要密码、不需要工号之外的任何个人信息。

### 1.2 「凭什么相信这个头」—— 整个系统的安全边界

请务必和贵方安全团队一起看这一节。

网关看到 `X-Agent-User: 张三的工号` 就会把请求送进张三的容器。
所以**任何能把这个头发进网关的东西，都能冒充任何人**。两道门，至少要有一道，建议都开：

| 门 | 做法 | 性质 |
|---|---|---|
| 共享密钥 | 贵方代理在每个请求上加 `X-Agent-Trust: <密钥>`，网关做常数时间比较 | 这是一个**持有即可冒充**的凭据。不要落在前端、不要进日志、不要写进版本库 |
| 来源网段 | 只接受来自指定网段的请求 | 防「有人拿到了密钥但不在贵方网络里」 |

**两道都没配时网关拒绝启动。** 这是刻意的：配漏了的网关是一个「任填工号即可进入任何人环境」
的接口，而从外面看它工作得完全正常 —— 这种缺口不会有人来报，只能靠起不来暴露。

还要请贵方代理做一件事：**剥掉客户端自带的这三个头**，再写入自己的值。
否则用户在浏览器里自己加一个 `X-Agent-User` 就绕过了认证。

### 1.3 工号格式约束

工号会被拼进容器名与 NAS 路径，所以有格式要求：

- 小写字母、数字、连字符；首尾必须是字母数字
- 最长 54 个字符
- 大小写不敏感（`U1234` 与 `u1234` 视为同一人）—— 大小写不统一会变成两个容器、两份历史

不合法的工号一律拒绝，且**错误信息里不回显原值**（它会被原样写进日志与错误页）。
贵方工号若含大写或下划线，请在代理侧转换后再发，或告知我方以便调整规则。

### 1.4 角色头（决定谁能导入知识库）

带了角色头且其中包含 `kb-admin`（值可配）的用户，会额外获得一个知识库导入入口。
普通用户没有这个入口 —— 不是隐藏，是根本没有那个容器。

不方便传角色头也可以：留空时网关改从集群里的一张名单判定，由运维维护。

### 1.5 反向代理的硬要求：关掉响应缓冲

**这是唯一一条硬要求。** 模型的回答是逐字推送的（SSE 长连接）。
代理若开着响应缓冲，用户会看到「提交后长时间没反应，然后整段一起蹦出来」，
更常见的表现是显示**「已中断」**。

- nginx：`proxy_buffering off;`（我方在响应里已带 `X-Accel-Buffering: no`，nginx 会自动识别）
- 读超时：请设到 **10 分钟以上**。一次深度诊断可能几分钟不出字
- 连接空闲：我方每 10 秒发一次心跳，正常不会触发空闲断开

### 1.6 可直接转发给统一认证团队的配置要求

> 请把认证成功后的请求转发到 `http://<接入网关地址>/`，并：
> 1. 加上 `X-Agent-User: <工号>`（小写，仅字母数字与连字符）
> 2. 加上 `X-Agent-Trust: <我方提供的密钥>`
> 3. 有角色体系的话加上 `X-Agent-Roles: <角色,逗号分隔>`
> 4. **先剥掉客户端自带的上述三个头**，再写入
> 5. 关闭响应缓冲，读超时 ≥ 10 分钟
> 6. WebSocket / SSE 需放行（`Connection` 与 `Upgrade` 头透传）
> 7. 路径不要重写：网关按原路径转发给容器

### 1.7 验收（两条命令）

```bash
# ① 不带信任凭据 —— 必须 403
curl -s -o /dev/null -w "%{http_code}\n" -H "X-Agent-User: <工号>" http://<网关>/session

# ② 带上凭据 —— 必须 200（首次 10~30 秒，网关在建环境）
curl -s -o /dev/null -w "%{http_code}\n" \
     -H "X-Agent-Trust: <密钥>" -H "X-Agent-User: <工号>" http://<网关>/global/health
```

第 ① 条返回 200 就是**安全边界没生效**，必须停下来查，不要继续往下走。

## 2. 给存储团队

### 2.1 要提供什么

一个 NFS 导出目录（RWX），容量按**人数 × 1–5 GB + 知识库**估算，
我方清单里的申领量是 500 GB，可按实际改。里面建三个子目录：

| 目录 | 放什么 | 谁写 |
|---|---|---|
| `users/` | 每个普通用户一个以工号命名的子目录：会话、历史、连接配置 | 该用户的容器 |
| `admins/` | 知识库管理员的同上目录 | 该管理员的导入容器 |
| `kb/` | 知识库：案例、条款、关系图、上传收件箱 | 导入容器写，普通用户容器**只读挂载** |

**三个子目录请预先建好，属主 uid/gid 都是 1000。**
容器以非 root（uid 1000）运行，目录不存在或属主不对时，容器起来但写不进去 ——
这种情况下用户能正常对话，**关掉浏览器后历史全没了**，而当时没有任何报错。

按工号的子目录不用预建，容器首次启动自己创建。

### 2.2 挂载参数

```
nfsvers=4.1, hard, local_lock=all
```

`local_lock=all` 是必需的：容器用文件锁做「同一目录不被两个容器同时写」的独占标记，
NFS 服务端锁在部分实现上不可靠。

### 2.3 容量与增长

| 内容 | 量级 |
|---|---|
| 单个用户目录 | 按 **1–5 GB** 估算（会话与历史本身很小，上传的文件与工作目录是主要部分） |
| 知识库 | 另算，取决于导入材料 |
| 异常终止留下的快照 | 每次一份，与当时的状态同体量 |

`.unclean-<时间戳>` 开头的目录是异常终止时留下的现场快照，**不会自动清理**。
确认不需要后可以删。它们存在本身就是一个信号：有容器被强杀或被驱逐过。

### 2.4 备份

这里存的是用户的对话历史和知识库，按贵方一般文件存储的策略备份即可。
**不需要停服**，也不需要特殊的一致性处理 —— 对话库的同步用的是数据库在线备份接口，
NAS 上那一份任何时刻都是可打开的完整文件。

### 2.5 不要做的事

- **不要**把 `users/<工号>` 做成多人共享 —— 那等于把别人的对话历史给他
- **不要**给普通用户目录之外的读权限；隔离靠「不挂载」，不靠权限位
- **不要**对 `kb/` 目录做去重或压缩类的后台改写，导入过程有写入互斥与原子写，
  外部改写会破坏这个保证

### 2.6 验收

```bash
kubectl -n gaussdb-agent get pvc              # nas 的 STATUS 是 Bound
kubectl -n gaussdb-agent exec deploy/runtime-<工号> -- sh -c \
  'touch /nas/me/.probe && rm /nas/me/.probe && echo "本人目录可写" ; \
   touch /nas/kb/.probe 2>/dev/null && echo "知识库可写——错了,应该只读" || echo "知识库只读 OK"'
```

必须看到「本人目录可写」和「知识库只读 OK」两行。

## 3. 给容器平台团队

### 3.1 集群前提

| 项 | 要求 |
|---|---|
| K8s 版本 | 1.24 以上 |
| CNI | **必须支持网络策略**（Calico / Cilium 等）。不支持的话我方给的隔离清单形同虚设 |
| 存储 | 支持 NFS 类型的 PV |
| 命名空间 | 一个，默认 `gaussdb-agent` |
| 节点架构 | x86 或鲲鹏。**鲲鹏镜像未在真实硬件上验证过**，上线前请留一次冒烟时间 |

### 3.2 镜像

五个，我方提供离线包（x86 与 arm64 各一份），请推入贵方内网仓库：

| 镜像 | 用途 | 副本 |
|---|---|---|
| runtime | 普通用户的容器 | 每个在线用户 1 个 |
| kb-import | 知识库管理员的容器 | 每个在线管理员 1 个 |
| gateway | 接入网关 | 2（常驻） |
| frontend | 四个大盘的静态页面（nginx，不读数据） | 1（常驻） |
| openGauss 7 | 知识库向量库 | 1（常驻） |

**请配置镜像保留策略。** 我方在测试环境三次遇到节点自动回收了未被引用的镜像，
表现是「昨天好的，今天建容器失败」。缩容到 0 的用户容器不引用镜像，正是被回收的对象。

### 3.3 网关需要的集群权限

网关要在本命名空间里建/删容器，权限范围如下，请照我方清单应用，**不要放宽**：

| 对象 | 允许 | 刻意不给 |
|---|---|---|
| deployments / services | 建、查、改、删 | — |
| secrets | 建、**按名取**、改、删 | **不给列举** —— 给了就等于一次请求拿到全体用户的口令 |
| configmaps | 查 | 改 |
| pods | 查 | **exec / attach / port-forward** —— 网关没有进用户容器的理由 |

权限仅限本命名空间，不需要集群级权限。

### 3.4 需要放行的出网地址

清单里是占位网段（`10.0.0.0/8`），**请改成实际地址**：

| 从 | 到 | 端口 |
|---|---|---|
| 用户容器 | 中间件 | 按实际 |
| 用户容器 | 模型服务 | 443 / 80 |
| 用户容器 | 向量库（集群内） | 5432 |
| 用户容器 | DNS | 53 |
| 网关 | K8s API Server | 按实际 |
| 网关 | 用户容器 | 4096 |
| 网关 | 用户容器（报告只读端口，大盘数据口） | 4097 |
| 网关 | 大盘前端（集群内） | 8080 |
| 上游 SSO / Ingress | 网关 | 80 |

大盘前端**只收网关的入站、不出网**，清单里已经这么写，不需要放行任何地址。

**用户容器不需要访问 K8s API，网关不需要访问中间件和数据库。** 请保持这个边界。

> 实测提醒：部分集群（如本地开发用的轻量集群）的 API Server 端点不在 Service 网段内，
> 只按 Service 网段放行会导致网关连不上 K8s。请用 `kubectl get endpoints kubernetes -n default`
> 看到的实际地址来配。

### 3.5 资源规格

| 组件 | requests | limits | 本地盘 |
|---|---|---|---|
| 用户容器 | 250m / 512Mi | 2 核 / 2Gi | 10Gi |
| 网关 | 100m / 128Mi | 1 核 / 512Mi | — |
| 大盘前端 | 50m / 64Mi | 200m / 128Mi | — |
| 向量库 | 500m / 1Gi | 2 核 / 4Gi | 20Gi |

按 **50 人、峰值 20 人同时在线**估：约 5 核 / 10Gi 常驻用量。
闲置用户会被自动回收（默认 30 分钟），不占用计算资源。

用户容器的本地盘是 `emptyDir`，**必须保留 sizeLimit**：撑爆会导致容器被驱逐，
而驱逐属于异常终止 —— 用户会丢最后不到一分钟的对话。

### 3.6 如果贵方已有容器管理框架

不想用我方网关也可以，两条路：

- **只用编排能力**：我方提供按工号渲染的容器模板，贵方框架负责建与销毁。
  但「认工号、找容器、代理、按活动回收」这几件事需要贵方实现
- **调我方控制接口**：网关提供列出容器、手动回收的接口，贵方框架调用它

两种做法的接口细节在 `接入手册-SSO与K8s.md` §3.5。

### 3.7 验收

```bash
kubectl -n gaussdb-agent get pod                       # 网关 2/2，向量库 1/1
kubectl -n gaussdb-agent logs -l app=agent-gateway --tail=3   # 一行「网关就绪」
# 网络策略确实在拦：访问一个没放行的地址，应该拿不到任何 HTTP 状态码
kubectl -n gaussdb-agent exec deploy/runtime-<工号> -- \
  curl -s -o /dev/null -m 5 -w "%{http_code}\n" http://<未放行的地址>
```

最后一条**必须**返回 `000`。返回任何 HTTP 状态码都说明策略没生效 ——
通常是 CNI 不支持网络策略，此时集群看起来一切正常，隔离却是纸面上的。

## 4. 给中间件团队

**这一节决定「某个人能诊断哪些数据库」，是整套方案里唯一我方管不到的隔离。**

| 要做的事 | 状态 |
|---|---|
| 按人签发令牌 | 需贵方确认。每个使用者一个，我方按工号取用 |
| 令牌背后绑定的数据库账号与白名单 | 需贵方确认 |
| 确认工号放在哪个字段 | 需贵方给字段名（请求头名 / 报文键名），我方两处都能发 |
| 确认签名口径 | 见下 |

我方已经能把调用人工号显式发给中间件，位置按贵方字段名配置；
**中间件是否据此做权限判定，取决于贵方。** 在此之前，能看到哪些库由令牌本身决定。

签名方面，过渡期可以只带 `Appkey` 与 `Timestamp`（秒），不带 `Signature`；
密钥到位后切到完整签名。切换是改一个配置值。以下三项请贵方明确：

1. 签名原文的拼法（我方默认 `<请求路径>+<时间戳>`）
2. 签名的编码与结构（十六进制/Base64；r‖s 拼接 / ASN.1）
3. **签名 userId 用哪个** —— 国标默认是一串定值，OpenSSL 默认是空串。
   这一项填错的表现是一律验签失败，没有其它症状

## 5. 给 AI 平台团队

| 要提供的 | 必需 | 说明 |
|---|---|---|
| 模型服务地址 | 是 | OpenAI 兼容接口，**地址要含 `/v1`** |
| 模型服务密钥 | 是 | 放入我方 Secret，不进配置文件 |
| 模型名 | 是 | |
| embedding 端点 + 模型 + 维度 | 否 | 不提供时知识库走文件模式 |

**embedding 是可选的。** 不配的话案例检索、条款检索、关系图全部可用，
只是少了语义检索（用不同说法描述同一个现象时找不到）。可以先上线，之后再配。

维度必须与模型实际输出一致。**换 embedding 模型必须重建索引** ——
同维度换模型而不重建，库里会混着两套向量空间：相似度失去意义，而覆盖率仍显示 100%。
我方已加拦截，换了模型不重建会直接拒绝。

## 8. 对接阶段最容易出的三件事

**一、安全边界没生效，而看不出来。**
表现：一切正常。查法：不带信任凭据访问必须 403（§1.7 第 ① 条）。
这是唯一一个「不主动查就永远不知道」的问题，请务必查。

**二、响应缓冲没关。**
表现：用户提交后长时间无反应，或界面显示「已中断」。
刷新浏览器可以恢复，但每次对话都会遇到。查法：改代理配置，不是我方问题。
