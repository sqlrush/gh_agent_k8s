# 版本说明

每个版本的镜像标签是 `agent-v<版本>-oc1.18.27`（`oc1.18.27` 是镜像里的 opencode 版本）。
升级步骤见《部署手册-从零到上线》§10.5：用户容器在下次登录时换新版，正在用的人不受影响。

## agent-v1.4.8（2026-11-06）

**紧急修复：api 模式登录时库名对不上就登录不了。** 中间件按实例 IP 固定连一个库（行方各实例都是 postgres），不按库名切换；
用户填业务库名时，登录时的库名核对（v1.1.6 加的）一律对不上、拒绝建会话——api 模式等于谁都登不上。从 v1.4.7 升级
（v1.4.3 ~ v1.4.6 也可以直接升，白名单照 v1.4.7 的说明导）；可以用发版台升级。

### 改动

- **api 模式登录：库名在实例上存在就放行**（gaussdb-login 1.3.4）。用户填的库名是「要诊断哪个库」，不是「连哪个库」。登录时核对：
  - 与中间件实际连的库一致：照常登录；只差大小写：按实际库名登录（与原来相同）。
  - **实例上有这个库、但中间件连的是另一个**：放行。会话与报告抬头按用户要诊断的库记，登录表格多一行「取数库」，并告诉用户：
    会话、锁等待、等待事件、慢 SQL / Top SQL、WDR 是整个实例的数据，照常可用（本版还没按库筛选，可能含实例上其他库的）；
    表、索引、执行计划、存储过程属于各自的库，只能看到取数库里的。
  - 实例上**没有**这个库（多半是写错）：仍然拦下，并列出实例上的库——v1.1.6 加这道核对要防的「库名写错、报告抬头写错、
    同一个库的历史劈成两份」照样防得住。
- **对其他库的 SQL 现取执行计划时说清真实原因**（gaussdb-explain 2.6.2、gaussdb-sqltune 2.8.3）：在取数库里找不到对象，原来提示
  「让 DBA 给执行账号设 search_path」——这时是误导（原因是库不对），而且要改数据库。改为说明是中间件按实例 IP 固定连库所致、
  改 search_path 与授权都解决不了；gaussdb-explain 按 `--sql-id` 调用时改给 SQL 历史里记下的**真实执行计划**
  （SQL 历史只在系统库里有数据、覆盖实例上全部库，取数库是 postgres 时正好取得到）。
- **发版台冒烟「只读诊断报告」误判失败**：每个实例只保留最近 50 份报告，攒满后新报告挤掉最老的一份、份数不再增加，原来只看份数就判成「没出报告」。改为份数不变时看最新一份报告的时间。
- **还没做的**（下一步）：会话、慢 SQL、Top SQL、WDR 按要诊断的库筛选；对其他库的 SQL 调优改为依据执行历史里的计划、执行统计与
  WDR 快照里的表与索引统计（不现取计划），解决「部分 SQL 无法调优」。

### 改动

- **诊断站在应用 DBA / 运维 DBA 的角度（行方 11-05 要求，本版核心）**：数据库指标异常要追到引起它的业务——哪条 SQL、哪个会话、
  哪个应用、哪张表、哪个操作；处置先改应用、再做运维操作，参数只在典型场景给，且只限允许清单。
  - **安全红线新增「站在应用 DBA / 运维 DBA 的角度」**（20 个技能与两份根提示词都带）；根提示词写明角色定位；回答模板的根因段要落到业务对象、
    处置按「应用 → 运维 → 参数」排序，「数据库机制」视角改为写给运维 DBA、不讲数据库内部实现；知识库里的已知缺陷先写业务侧排查结论再转述。
  - **参数允许清单**（`common/guc_policy.py`，只维护一份）：典型场景可建议的只有最大连接数（开线程池时配套线程池大小）、autovacuum 并发与触发阈值，
    给方向不给数值、写明「需运维评估」；表级 / 会话级设置（表级存储参数、某条 SQL 的会话级 `work_mem`、DDL 会话上的 `lockwait_timeout`）写在应用侧处置里；
    缺监控数据时只说明需运维开启哪个开关；配置审计发现的与可靠性 / 安全基线不符的照报，交运维核对。`random_page_cost`、`shared_buffers`、
    `checkpoint_segments` 等不再作为建议出现。守卫测试扫描全部技能的输出与文档，回答检查也按它核对。
  - **各技能的输出改为业务视角**：等待事件的每条发现给出同一时段追到 SQL / 会话的命令（不再停在「某类等待占比高」）；WDR 的等待倾斜改为在
    Top SQL 里找元凶请求、锁类回看同一时段谁持锁；健康检查与 WDR 方法论里 WAL / checkpoint / 轻量锁 / 缓存命中率改为先找写入或访问它的业务；
    vacuum 报告不再印内核事务水位与 clog / csnlog，内存分析不再写「疑似泄漏 / 碎片」（改为指向长连接、对象数），SQL 调优报告不再印优化器内部常数。
- **三个例子补上能力**（行方原话里的三个场景）：
  - **大字段写入导致 xlog 膨胀**：健康检查新增 WAL 维度——隔 5 秒采两次算出 xlog 每秒生成量（`WAL_RATE_HIGH`），并给出写入最多的表
    （大字段写入折回所属业务表）、写入行数最多的业务 SQL，库支持时（GaussDB）再给出当前事务 xlog 用量最大的会话；WDR 新增「写入来源」一节
    （时段内各表写入与 redo 量）；Top SQL 新增 `--by writes`（按写入行数排）。
  - **DDL 长时间锁表**：锁等待分析识别 DDL；排在「等锁的 DDL」后面的业务会话补回明细（原来与持锁者不冲突、被当旁观者滤掉）；
    新增 `LOCK_QUEUE_BEHIND_DDL`（P0 是先取消等锁的 DDL 放行队列）与 `LOCK_DDL_HOLDER`。
  - **大量子事务导致 xmin 推不动**：vacuum 用官方给的定位方法指出**真正持有最老 xmin 的会话**（应用、用户、正在执行的语句、事务时长），
    给出 xmin 落后多少个事务号；正在执行存储过程的提示查循环里的 EXCEPTION 块（每进入一次建一个子事务）；死元组写明来自这张表多少次更新 / 删除。
  - 白名单新增 9 条、更新 2 条（`scripts-delta-20261105.sql`）。og5（openGauss 5.0.3）上没有的列（按会话的 xlog 用量）技能如实说明「本库不支持」。
- **登录与写操作请求（11-06 首轮验收发现）**：api 模式登录先看部署时登记的实例别名——登录脚本缺参数时直接列出别名、写明用 `--alias` 登录，
  提示词也改为「先看别名，不在清单里才向用户要实例 IP 和库名」（首轮有 5 道题因为模型去问用户要 IP 而没取到数）；用户要求终止会话、改参数等
  写操作时，先说明不能执行，同时直接用对应技能查证，再给人工处置路径（不再只拒绝或反问「需要我查吗」）。
- **两个交付包与转化脚本**：诊断技能包（17 个诊断技能 + `gaussdb-kb`、SQL 白名单）与知识库导入技能包（`gaussdb-kb-import`、`gaussdb-kb-init` +
  `gaussdb-kb`）从同一份源码按交付清单 `delivery/manifest.py` 生成。common 只有一份，每个文件标明归属（两包共用 / 只诊断 / 只导入），守卫测试核对
  每个文件恰好一个归属、共用部分不依赖只属于某一包的模块、每个技能的依赖都在本包里。转化脚本装配后自检——文件与清单逐个对上、每个技能脚本在
  交付包里真 import 一遍、不含测试环境路径 / 行名 / 密钥 / 内网 IP / 对模拟组件的调用、白名单定义与 DML 逐条一致——并自动生成
  `补充说明.md`（版本对应、依赖、环境变量与默认值、白名单变化、根规范目录约定、变更摘要）。同一标签生成结果逐字相同，内容没变不提交，
  交付分支被手改就停下；执行人的机器上只需要 git + Python 3.9+。用法见 `delivery/README.md`。两个包都带根规范检索脚本 `rootspec/search_docs.py`（两份根提示词都要执行它；镜像里是 `/workspace/search_docs.py`）。
- **知识库层不再读登录会话**：查知识库时用的连接别名改由诊断侧（`common/kbsection.py`）传入，`common/kb/` 不再依赖登录模块。行为不变。
- **技能文档更正**：锁等待、vacuum、等待事件三个技能里 `config.yaml` 的默认位置写成实际的 `/workspace/.opencode/skills/common`
  （原来写的是单机版的 `~/.gdaa`）；知识库导入的存储配置示例、登录脚本注释里的示例地址改为占位写法；注释里不再引用只在测试仓库里的工具，测试记录统一称「故障演练」（只改注释）。
  技能版本（本版改了内容的）：gaussdb-health 3.8.0、gaussdb-vacuum 1.4.0、gaussdb-lockwait 1.5.0、gaussdb-topsql 2.5.0、gaussdb-wdr 2.7.0、gaussdb-waitevent 1.3.0、gaussdb-config 1.2.0、
  gaussdb-memanalyze 1.1.1、gaussdb-sqltune 2.8.2、gaussdb-proctune 2.5.1、gaussdb-explain 2.6.1、gaussdb-slowsql 2.2.1、gaussdb-topproc 2.0.4、gaussdb-procinfo 2.3.1、gaussdb-kb-import 4.3.1、gaussdb-login 1.3.3。
- **验收题库迁入本仓库**：`acceptance/`（跑题、评分、出报告）与《智能体验收方案》从联合仓库迁来，不随离线包发出；在线页面仍在联合仓库。
  故障演练工具 `agent/tools/faultlab/` 也从 gh_skill 迁来，新增场景 W1（大字段批量写入）；题库新增 5 题（B9 xlog 涨得快、B10 DDL 等锁堵住读写、B11 死元组清不掉是谁卡住、H7 指标高就是数据库有 bug 吗、H8 连接数调到多少合适），共 53 题；回答检查的视角三条计入版式分。白名单增量与清单改由本仓库的 `agent/tools/delivery_delta.py`、`agent/tools/whitelist_doc.py` 生成。

### 已知限制

- 两个包都带 common 的连接层（config / credential / db / backends / session）：`common/__init__.py` 统一导出连接相关的名字，所有技能都从这里取。
  导入包不连库，但带着这几个文件；拆开要改全部技能的导入写法，留到以后。
- 执行人的机器上没装 PyYAML 时，转化脚本跳过知识库契约注入的核对与部分脚本的导入检查（打印「提示」，其余检查照做）；正式生成建议在装了 PyYAML 的机器上做。

  路径一律写环境变量（技能目录 `$GSDB_SKILLS_DIR`、本行知识库 `$GSDB_KB_DIR`、根规范 `$GSDB_ROOTSPEC_HOME`），不写测试环境的绝对路径，

### 新功能

- **固定池化**（可选的部署形态，取代 v1.2.0 的池化沙箱）：部署时固定 N 个 Pod、每个 Pod K 个槽位，运行中不建、不删、不补；
  N 人以内各自独占一个 Pod，多出来的人共用。人走了**粘性保留**：先写回 NAS，槽位仍归他，回来 0–1 秒恢复；只在缺槽位或超过保留期时腾挪。
  满员时把闲置最久的在用者提前转保留、腾出的槽位留给等待的人，等待页每 30 秒自动重试。同 Pod 的人之间：各自的盘与进程空间、
  端口防冒充、腾挪即重启清盘。《固定池化手册》。
- **凭据不再进入模型所在的容器**：中间件令牌、SM2 签名私钥、模型 Key 由凭据代理在转发时加上——按需模式是用户 Pod 里的伴生容器，
  固定池化是 Pod 的管家。代理只往配置的中间件与模型地址转发、只转诊断接口，工号按本人强制写入。模型即使执行命令读环境变量，
  也读不到任何凭据。
- **opencode 工具权限真正执行**：原来写在 AGENTS.md 里的权限只是提示词，现在写进 opencode 的配置：不能联网、只能用 gaussdb-* 技能，
  命令行只放行技能脚本与几个只读命令（拒绝读环境变量、读 `/proc`、重定向写文件等）；诊断容器不能改文件，知识库导入容器可以（写草稿）。
- **回答模板化**：健康检查、故障排查、SQL 优化、知识问答、WDR 解读、Top SQL / 慢 SQL 榜单各有固定版式，共用开头（总体状态 → 短结论）
  与结尾（「需要就 xxx 展开说明吗？」）；正文每段先「应用视角」（给开发人员）、再「数据库机制」（给数据库工程师）。
  SQL 优化增加现状与趋势（执行次数、平均 / 最大耗时、近 7 天按小时的变化、哪个时间点突然变慢、当时执行计划变没变）与改写前后对比；
  WDR 报告重排为负载画像 → 问题与元凶 → 解决方案 → 总结和结论 → 附录。测试环境前后对比：版式检查从 7/62 项到 52/52 项。
- **知识引用上色并注明出处**：出自客户知识库的句子写进正文并上色，句后括号注明出处，例如「……（引用自贵行规范库 GS-CHG-003）」；
  贵方自己的规范、案例、手册、基线等蓝色 `#2f6fdb`，产品文档（官方文档集与导入的产品文档）青色 `#0f7c86`；诊断结果与通用经验不上色，
  一眼分得清哪些话是贵方自己的口径。知识库里没有时统一写「知识库中未找到相关内容，以下为通用知识，仅供参考」。
  复制到工单等纯文本处时会带上 `<font …>` 标签。
- **知识类型标签（八类）**：规范、案例、环境画像、指标基线、已知缺陷、处置手册、产品文档、Wiki。类型 = 目录，
  每类按自己的要点校验（手册要执行前提与回退、缺陷要受影响版本与厂商结论、产品文档要产品系列与版本、画像不许写地址与口令）；
  导入时模型提议类型、人确认、脚本校验落盘（`kb.py template / add / attach / retype / migrate / profile / taxonomy`）。
  案例增加排查思路小节（候选原因、取证顺序、排除理由、最终验证）与**区分证据**：同一现象本行有过不同根因时，
  导入审核与 `validate` 都会提示补。
- **渐进式披露（L0–L3）**：`index` 生成 L0 总索引（八类各多少、适用环境、专题入口）与每个专题的 L1 导航
  （同义词、本行确认过的候选原因与区分证据、按类型分组的条目摘要），都有字数上限；
  模型按层取：`kb.py overview / topic / show / evidence`，引用步骤、审批、版本结论前必须 `show` 读全文。
- **适用性判断**：条目与本实例画像的产品系列、版本、系统不符时标「不适用本环境」并降权；已知缺陷写「本环境版本受影响 / 不受影响」；
  别的系统的指标基线不出；基线只并列展示，不改 severity。
- **官方文档集**：GaussDB 官方文档（CHM）按目录切分成标准知识库的一层（条目 ID `PD-<代号>-NNNNN`，永不复用），
  导入时逐项向用户确认范围、产品系列与版本；换下一版文档时另起代号导入，旧的整体退役。
- **等待事件 / vacuum / WDR / 内存 / 存储过程 / SQL 审核单独运行也检索客户知识库**：原来只有健康检查、锁等待、SQL 调优在脚本里查。
- **大盘知识库页显示类型与专题标签**：总览上列出八类各多少（为 0 的灰显，点一类直接筛选）；新增「知识条目」页签，
  八类知识放在一张清单里按类型 / 专题筛选、搜索，右侧显示条目全文、适用产品与版本、验证状态、审批依据与出处；
  案例、条款详情也带类型与专题。数据与模型检索读的是同一份目录（同一口径），未审核的收件目录与原件照旧不上大盘。
- **大盘所有「深挖」入口都带上报告的时间**：头条解读卡的追问、页头「在会话里深挖」、「重新巡检 / 重新取数」、Top SQL 的深挖与调优、
  sql_id 抽屉的「看执行计划 / 调优」、⌘J / ⌘K 的提问。有评估窗口的带窗口，此刻巡检 / 累计榜带取数时间——看的是几天前的报告时，
  模型不会去取现在的数。

- **中间件接口路径前缀改为部署配置**（`agent-config` 的 `GRMP_PATH_PREFIX`），代码里不再写死；没配时登录与凭据代理都直接报清楚、不拿猜的前缀去请求中间件，`runtime-doctor` 的 ① 也会查。

  已有知识库后配上 embedding 不加 `--fill-missing` 时向量覆盖率停在 0。现在都能查到；后配 embedding 再跑一次 `kb.py index` 就补齐。

以下是 2026-10-24 在测试库上用 faultlab 造出 34 类典型故障、两轮逐项核对技能时测出的（涉及白名单的见上表）：

- **健康检查漏报长事务 / 空闲事务**，vacuum 找不到卡住回收的事务、「最老事务」显示无：认客户端会话的条件只认 openGauss 自带驱动，
  psycopg2 等客户端整类被滤掉。改按客户端端口认。
- 健康检查：从没 ANALYZE 过的表进不了「统计信息过期」；开了线程池时连接数把空闲工作线程也算进去（虚高）；
  新增「执行中的长 SQL」判定（等锁的只计数）；死锁给不出「距上次新增」时写明原因。
- **锁等待的时段回看最近几个小时一律「回看不了」**：活跃会话采样先在内存、写满才落表，原来只读落表的那张。现在两处合并；
  健康检查时段体检的锁维度跟着恢复。行锁 / 事务号锁不再套用表锁的说明。
- 内存分析：线程池工作线程的负值标为不可信；「enable_resource_record 没开」是误报（参数清单漏了它）；历史视图的峰值 / 下盘列对应改正。
- WDR：等待事件段列出每个等待类里的主要事件（如 WALFlushWait）。
- SQL 调优：按 sql_id 调优时占位符被误判成 IN 列表、整个调优失败；EXPLAIN 拒绝合成值时自动换值重试。
  新增根因提示：相关子查询逐行执行、NOT IN 子计划（含 NULL 语义）、索引列被类型转换或函数包住、LIKE 拼接关联、左模糊。
- Top SQL：榜上加「CPU+IO」与「等待占比」，等待占比高的点名引导去看锁；新增按自身耗时排序（`--by self` / `self_avg`），
  被锁挡住的语句不再占满榜首。
- 大盘：报告文件取不到时（索引里还登记着）退回离它最近的同类报告并写明，不再整页「HTTP 404」；下次存档自动清掉失效的索引条目。
- 固定池化：保留期间 NAS 上的数据丢了（误删、恢复不全），回来时用槽位里的保留副本恢复并写回，不再判过期把唯一的副本清掉。

| （建议）DBA 评估数据库保留期参数 | 时段锁回溯靠活跃会话采样（`asp_retention_days`，默认 2 天）；历史真实执行计划靠语句历史（全量 SQL 最长保留 24 小时）。见部署手册 §0.4 |

### 新功能

- **时段锁回溯**（`gaussdb-lockwait --from … --to …`）：从数据库自带的活跃会话采样（ASP）事后还原某段时间里谁挡了谁——阻塞对、阻塞链与根、根会话的状态 / 应用 / 事务开始时间、约等了多久（采到次数 × 约 10 秒，估算）。事后回看不生成 kill 语句。时段体检终点在过去时，「锁与阻塞链」不再是「回看不了」，改由它填。
- **历史真实执行计划**：按 sql_id 看执行计划时，语句文本带占位符（无法重新 EXPLAIN）或被截断，先给语句历史里记下的当时真实执行的计划（带实际耗时与行数），标明是哪次执行。
- **WDR 附录带真实计划**：WDR 采集时取根因语句在窗口内的真实执行计划，附录直接展示，不再写「本次未取到」。
- **部署手册 §0.4 / 对接清单 §5**：写明事后分析能回看多久取决于哪些数据库参数（语句历史、活跃会话采样、WDR 快照的保留期），由 DBA 评估开启。

### 修复

- sqltune / explain：`schema_name` 是搜索路径串（如 `fl, public`）时按逗号拆开逐段校验并整串切换，不再报「不是合法标识符、未切换 search_path」。
- explain：文本是归一化的时，报错不再一律说「statement_history 里没有这条」。
- 大盘：时段体检「深挖」首句的评估窗口带秒。原来只到分钟，深挖时起点退到上一个快照，窗口变宽、平均活跃会话被摊薄，和卡片上的数对不上。

### 新功能

- **时间段的 Top SQL 与健康检查**：「最近 30 分钟」「10:46 到 11:07」都能问。取包住这段时间的 WDR 快照 / 自留采样 / 此刻两端相减——不追求精确、只保证覆盖住，并写明要的是哪段、实际评估的是哪段、为什么；跨过实例重启时只覆盖重启之后那段。时段体检里连接、锁、膨胀等瞬时状态逐项写明「回看不了」；终点是此刻时给当前值并标明。
- **死锁日志解析**（`gaussdb-lockwait --deadlock-log -`）：用户把日志里 `deadlock detected` 那几段贴进对话，解析出环、语句、牺牲者，按模式给出改法。不依赖日志前缀，不连库。WDR 与健康检查报死锁次数时会引导用户贴日志。
- **新技能 `gaussdb-config`（参数体检）**：只报客观错误——参数自相矛盾、会静默丢数据的危险配置、按实例内存预算算出的超卖；不给凭空的推荐值。
- **健康检查补六项**：冻结水位、占用量、同步提交与部署形态、WAL 复制槽、线程池用量、分区数。**膨胀估算**（空间比应占多了多少）。
- **WDR**：各维度元凶从耗时前 200 条里找，榜外冠军另列；临时溢出写明能归到语句的占多少、冠军是哪条（带 sql_id，后续调优直接用）；点 sql_id 看全文与执行计划；报告给出确定性的「下一步」。
- **大盘显示时段报告**：对话里给的链接直接打开那一份时段榜 / 时段体检；按评估窗口筛选；深挖首句带评估窗口。

### 修复

- **WDR 的 DB time 少报约 8800 倍、Top SQL 漏掉窗口内新出现的语句**；文件 IO / 缓存 / 库统计同样的内连接漏行（文件 IO 实测 1468 个文件只统计到 185 个）。
- **空闲库被判告警**：每小时 DB time 零点几秒的窗口里「LWLOCK 占 DB time 171.8%」被判 🟠。现在空闲窗口不判比例；等待占比与 DB time 自相矛盾时明说不可信、不判告警。
- **Top SQL**：同一语句按执行用户拆成多行时重复上榜、增量算错；SQL 开头的注释占满显示宽度；「最近 10 分钟」原来会阻塞 10 分钟（现在回看已有的采样 / 快照，不阻塞）。
- **sql_id 查不到**：说清原因（实例何时重启），语句在 WDR 存档里有文本时直接给出并指路出计划。
- **对话里的大盘链接点不开**（原来给的是裸路径）；报告里不再出现让模型照抄的命令行。
- 健康检查在单机库上把「同步提交」误报为风险；冻结水位误写为「会停写」（本内核是 64 位事务号）。
- 参数体检不再拿 `reset_val` 判「改了未生效」（本内核上 108 个参数的 `reset_val` 没有有效值）。

## agent-v1.2.0（2026-10-16）

### 升级前先看

| 要做的事 | 为什么 |
|---|---|
| 重新 `kubectl apply` 网关的清单 `k8s/base/gateway.yaml` | 网关的权限新增本命名空间内 **Pod 的 get / list 与事件的 list（只读）**，用来在用户容器起不来时说清原因。不重新 apply 也能运行，只是起不来时仍只会说「正在启动」 |
| 检查 ConfigMap `agent-roles` 里 `kb-admins` 的名单 | 网关**从这一版起才真正读这张表**（以前手册写了、网关没读）。表里的人都会成为知识库管理员；交付样例里原来的示例工号已删除 |
| 确认 NAS 上的 `users/`、`admins/` 属主是 1000:1000、权限 775 | 新工号首次登录时，由用户容器的初始化步骤以 uid 1000 建个人目录，前提是上一层可写（这本来就是部署要求，§2.1） |

| 数据库白名单 | **不需要重新导入**：这一版没有新增或修改白名单脚本 |

### 修复

- **第二次打开大盘整页空白。** 网关给没有消息体的响应（304 / 204 / HEAD）也加了分块编码，浏览器复用连接时把多出来的字节当成下一个响应，一个模块坏掉整页就空白。模拟 SSO 工具（`k8s/tools/sso-sim.py`）同样修了。
- **新工号首次登录，用户容器反复重启。** 个人目录被自动建成 root 属主、容器写不进。现在由初始化容器以 uid 1000 建好并确认可写；建不了时把原因与修复命令写进容器状态。
- **用户容器起不来时，用户等满 120 秒只看到「正在启动」，网关日志里没有原因。** 现在网关读 Pod 状态与事件，归成一类原因：拉不到镜像、容器配置缺失、个人目录初始化失败、NAS 挂不上、调度不上。前三类等下去也不会好，网关不再等满超时，当场回 503；网关日志写完整原因，给用户只说是哪一类。
- **写进 `agent-roles` 的知识库管理员不生效。** 网关现在读这张表（30 秒内生效），与角色头两者满足一个即可。
- **管理员进不了知识库导入容器。** 网关以前只转发到诊断容器。现在访问 `/kb-import/` 切到导入容器、`/runtime/` 切回；也可由 SSO 给管理员入口加请求头 `X-Agent-Target: kb-import`（接入手册 §2.5）。
- **中间件模式下库名写错不报错。** 库名不发给中间件，写错只会变成报告抬头上的错误标签。现在登录时核对，不一致就不登录，并告诉用户实际的库名。
- **镜像放在内网仓库时，用户一登录就 504。** 网关新增 `USER_IMAGE_REGISTRY`（用户容器镜像的仓库前缀）。
- **`delete` 回收模式会把这个人的平台令牌一起删掉。** 管理员的导入容器一闲置，正在用的诊断容器与 `grmp-token-<工号>` 跟着被删，下次登录报「尚未开通」。现在只删闲置的那一个容器。
- **用户容器在对话进行中被删除时，网关把那条连接写坏。** 现在干净地结束。

### 新功能

- **大盘两种风格**：普通（运维舱）与文艺（「GaussDB智能体日报」），页面顶部滑块切换，选择记在浏览器里。
- **从对话直达大盘**：健康检查、Top SQL、WDR 跑完后，智能体在回答末尾给出这一份报告在大盘上的链接。
- **大盘按时间段筛选**已经跑过的报告（顶栏「时间段」）。WDR 按快照窗口算。
- **实例别名**：在 `agent-config` 的 `GRMP_INSTANCE_ALIASES` 登记「别名=实例IP/库名」，用户说别名时智能体能直接登录（参数手册「实例别名」）。
- **WDR 按时间段定窗口**：用户说「15:16 到 15:26 那次故障」时，由脚本算出刚好围住它的快照窗口；围不住时说清缺哪一头。
- **一键诊断 / 修复** `k8s/tools/runtime-doctor.sh <工号>`：配置与开通、个人目录、用户容器、从集群里实测出网、出网策略、本机代理；`--fix` 修能自动修的；`--login` 经网关真登录一次，看容器会不会被反复收掉（部署手册附录 A）。
- **池化沙箱**（可选的第二种部署形态）：平台预先拉起一批沙箱，用户登录时绑定、退出时持久化（《池化接入手册》）。现有的按需模式不受影响。
- **第 5 个镜像** `gaussdb-agent-vectordb`：用 openGauss 官方二进制包构建的知识库向量库（也可直接用官方镜像）。
