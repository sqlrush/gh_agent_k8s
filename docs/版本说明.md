# 版本说明

每个版本的镜像标签是 `agent-v<版本>-oc1.18.27`（`oc1.18.27` 是镜像里的 opencode 版本）。
升级步骤见《部署手册-从零到上线》§10.5：用户容器在下次登录时换新版，正在用的人不受影响。

## agent-v1.3.1（2026-10-22）

### 升级前先看

| 要做的事 | 为什么 |
|---|---|
| **中间件团队导入白名单增量** `scripts-delta-20261022.sql`（新增 5 条；首次部署用全量 `scripts.sql`，共 123 条；从 v1.2.0 及更早升级的先导 `scripts-delta-20261018.sql` 再导这一份） | 时段锁回溯与历史真实执行计划要用新脚本。不导也能升级、不会报错，但这两项会明说「取数失败、白名单里还没有这几条脚本」，其余功能不受影响 |
| 四个镜像与 `USER_IMAGE_TAG` 一起改成 `agent-v1.3.1-oc1.18.27` | 有测试保证清单里三处一致 |
| 大盘前端与用户镜像**一起升** | 深挖首句的评估窗口改为带秒，与新版技能配套 |
| 网关清单 | **不需要重新 apply**：这一版网关与 K8s 清单除镜像标签外没有改动 |
| （建议）DBA 评估数据库保留期参数 | 时段锁回溯靠活跃会话采样（`asp_retention_days`，默认 2 天）；历史真实执行计划靠语句历史（全量 SQL 最长保留 24 小时）。见部署手册 §0.4 |

### 新功能

- **时段锁回溯**（`gaussdb-lockwait --from … --to …`）：从数据库自带的活跃会话采样（ASP）事后还原某段时间里谁挡了谁——阻塞对、阻塞链与根、根会话的状态 / 应用 / 事务开始时间、约等了多久（采到次数 × 约 10 秒，估算）。事后回看不生成 kill 语句。时段体检终点在过去时，「锁与阻塞链」不再是「回看不了」，改由它填。
- **历史真实执行计划**：按 sql_id 看执行计划时，语句文本带占位符（无法重新 EXPLAIN）或被截断，先给语句历史里记下的当时真实执行的计划（带实际耗时与行数），标明是哪次执行。
- **WDR 附录带真实计划**：WDR 采集时取根因语句在窗口内的真实执行计划，附录直接展示，不再写「本次未取到」。
- **部署手册 §0.4 / 对接清单 §5**：写明事后分析能回看多久取决于哪些数据库参数（语句历史、活跃会话采样、WDR 快照的保留期），由 DBA 评估开启。

### 修复

- sqltune / explain：`schema_name` 是搜索路径串（如 `fl, public`）时按逗号拆开逐段校验并整串切换，不再报「不是合法标识符、未切换 search_path」。
- explain：文本是归一化的时，报错不再一律说「statement_history 里没有这条」。
- 大盘：时段体检「深挖」首句的评估窗口带秒。原来只到分钟，深挖时起点退到上一个快照，窗口变宽、平均活跃会话被摊薄，和卡片上的数对不上。

## agent-v1.3.0（2026-10-19）

### 升级前先看

| 要做的事 | 为什么 |
|---|---|
| **中间件团队导入白名单增量** `scripts-delta-20261018.sql`（新增 13 条、更新 9 条；首次部署用全量 `scripts.sql`，共 118 条） | 新功能要用新脚本；被更新的 9 条里有 WDR 的取数修正。不导也能升级、不会报错，但时段功能用不了、WDR 仍跑旧 SQL（部署手册 §10.5 第 0 步） |
| 四个镜像与 `USER_IMAGE_TAG` 一起改成 `agent-v1.3.0-oc1.18.27` | 有测试保证清单里三处一致 |
| 大盘前端与用户镜像**一起升** | 时段报告的页面字段由新版技能产出 |
| 网关清单 | **不需要重新 apply**：这一版网关与 K8s 清单除镜像标签外没有改动 |

### 新功能

- **时间段的 Top SQL 与健康检查**：「最近 30 分钟」「10:46 到 11:07」都能问。取包住这段时间的 WDR 快照 / 自留采样 / 此刻两端相减——不追求精确、只保证覆盖住，并写明要的是哪段、实际评估的是哪段、为什么；跨过实例重启时只覆盖重启之后那段。时段体检里连接、锁、膨胀等瞬时状态逐项写明「回看不了」；终点是此刻时给当前值并标明。
- **死锁日志解析**（`gaussdb-lockwait --deadlock-log -`）：用户把日志里 `deadlock detected` 那几段贴进对话，解析出环、语句、牺牲者，按模式给出改法。不依赖日志前缀，不连库。WDR 与健康检查报死锁次数时会引导用户贴日志。
- **新技能 `gaussdb-config`（参数体检）**：只报客观错误——参数自相矛盾、会静默丢数据的危险配置、按实例内存预算算出的超卖；不给凭空的推荐值。
- **健康检查补六项**：冻结水位、占用量、同步提交与部署形态、WAL 复制槽、线程池用量、分区数。**膨胀估算**（空间比应占多了多少）。
- **WDR**：各维度元凶从耗时前 200 条里找，榜外冠军另列；临时溢出写明能归到语句的占多少、冠军是哪条（带 sql_id，后续调优直接用）；点 sql_id 看全文与执行计划；报告给出确定性的「下一步」。
- **大盘显示时段报告**：对话里给的链接直接打开那一份时段榜 / 时段体检；按评估窗口筛选；深挖首句带评估窗口。

### 修复

- **WDR 的 DB time 少报约 8800 倍、Top SQL 漏掉窗口内新出现的语句**；文件 IO / 缓存 / 库统计同样的内连接漏行（文件 IO 实测 1468 个文件只统计到 185 个）。
- **空闲库被判告警**：每小时 DB time 零点几秒的窗口里「LWLOCK 占 DB time 171.8%」被判 🟠。现在空闲窗口不判比例；等待占比与 DB time 自相矛盾时明说不可信、不判告警。
- **Top SQL**：同一语句按执行用户拆成多行时重复上榜、增量算错；SQL 开头的注释占满显示宽度；「最近 10 分钟」原来会阻塞 10 分钟（现在回看已有的采样 / 快照，不阻塞）。
- **sql_id 查不到**：说清原因（实例何时重启），语句在 WDR 存档里有文本时直接给出并指路出计划。
- **对话里的大盘链接点不开**（原来给的是裸路径）；报告里不再出现让模型照抄的命令行。
- 健康检查在单机库上把「同步提交」误报为风险；冻结水位误写为「会停写」（本内核是 64 位事务号）。
- 参数体检不再拿 `reset_val` 判「改了未生效」（本内核上 108 个参数的 `reset_val` 没有有效值）。

## agent-v1.2.0（2026-10-16）

### 升级前先看

| 要做的事 | 为什么 |
|---|---|
| 重新 `kubectl apply` 网关的清单 `k8s/base/gateway.yaml` | 网关的权限新增本命名空间内 **Pod 的 get / list 与事件的 list（只读）**，用来在用户容器起不来时说清原因。不重新 apply 也能运行，只是起不来时仍只会说「正在启动」 |
| 检查 ConfigMap `agent-roles` 里 `kb-admins` 的名单 | 网关**从这一版起才真正读这张表**（以前手册写了、网关没读）。表里的人都会成为知识库管理员；交付样例里原来的示例工号已删除 |
| 确认 NAS 上的 `users/`、`admins/` 属主是 1000:1000、权限 775 | 新工号首次登录时，由用户容器的初始化步骤以 uid 1000 建个人目录，前提是上一层可写（这本来就是部署要求，§2.1） |
| 四个镜像与 `USER_IMAGE_TAG` 一起改成 `agent-v1.2.0-oc1.18.27` | 有测试保证清单里三处一致 |
| 数据库白名单 | **不需要重新导入**：这一版没有新增或修改白名单脚本 |

### 修复

- **第二次打开大盘整页空白。** 网关给没有消息体的响应（304 / 204 / HEAD）也加了分块编码，浏览器复用连接时把多出来的字节当成下一个响应，一个模块坏掉整页就空白。模拟 SSO 工具（`k8s/tools/sso-sim.py`）同样修了。
- **新工号首次登录，用户容器反复重启。** 个人目录被自动建成 root 属主、容器写不进。现在由初始化容器以 uid 1000 建好并确认可写；建不了时把原因与修复命令写进容器状态。
- **用户容器起不来时，用户等满 120 秒只看到「正在启动」，网关日志里没有原因。** 现在网关读 Pod 状态与事件，归成一类原因：拉不到镜像、容器配置缺失、个人目录初始化失败、NAS 挂不上、调度不上。前三类等下去也不会好，网关不再等满超时，当场回 503；网关日志写完整原因，给用户只说是哪一类。
- **写进 `agent-roles` 的知识库管理员不生效。** 网关现在读这张表（30 秒内生效），与角色头两者满足一个即可。
- **管理员进不了知识库导入容器。** 网关以前只转发到诊断容器。现在访问 `/kb-import/` 切到导入容器、`/runtime/` 切回；也可由 SSO 给管理员入口加请求头 `X-Agent-Target: kb-import`（接入手册 §2.5）。
- **中间件模式下库名写错不报错。** 库名不发给中间件，写错只会变成报告抬头上的错误标签。现在登录时核对，不一致就不登录，并告诉用户实际的库名。
- **镜像放在内网仓库时，用户一登录就 504。** 网关新增 `USER_IMAGE_REGISTRY`（用户容器镜像的仓库前缀）。
- **`delete` 回收模式会把这个人的平台令牌一起删掉。** 管理员的导入容器一闲置，正在用的诊断容器与 `grmp-token-<工号>` 跟着被删，下次登录报「尚未开通」。现在只删闲置的那一个容器。
- **用户容器在对话进行中被删除时，网关把那条连接写坏。** 现在干净地结束。

### 新功能

- **大盘两种风格**：普通（运维舱）与文艺（「GaussDB智能体日报」），页面顶部滑块切换，选择记在浏览器里。
- **从对话直达大盘**：健康检查、Top SQL、WDR 跑完后，智能体在回答末尾给出这一份报告在大盘上的链接。
- **大盘按时间段筛选**已经跑过的报告（顶栏「时间段」）。WDR 按快照窗口算。
- **实例别名**：在 `agent-config` 的 `GRMP_INSTANCE_ALIASES` 登记「别名=实例IP/库名」，用户说别名时智能体能直接登录（参数手册「实例别名」）。
- **WDR 按时间段定窗口**：用户说「15:16 到 15:26 那次故障」时，由脚本算出刚好围住它的快照窗口；围不住时说清缺哪一头。
- **一键诊断 / 修复** `k8s/tools/runtime-doctor.sh <工号>`：配置与开通、个人目录、用户容器、从集群里实测出网、出网策略、本机代理；`--fix` 修能自动修的；`--login` 经网关真登录一次，看容器会不会被反复收掉（部署手册附录 A）。
- **池化沙箱**（可选的第二种部署形态）：平台预先拉起一批沙箱，用户登录时绑定、退出时持久化（《池化接入手册》）。现有的按需模式不受影响。
- **第 5 个镜像** `gaussdb-agent-vectordb`：用 openGauss 官方二进制包构建的知识库向量库（也可直接用官方镜像）。
- **文档**：《从源码构建到K8s运行-完整手册》《现场测试-模拟SSO》。
